# 神州 HR V1.9 · React 实施注意事项

更新日期：2026-07-22  
交付对象：UmaDev / React 前端 / 后端契约负责人 / QA

## 1. 基线与文件边界

- 唯一设计基线是 `V19-OD-00`；V19-OD-01～16 是在该基线上的独立交付物。
- 路由必须以 `route-to-artifact.json` 为当前设计注册表，不能从旧 V1.7 页面恢复导航。
- 不修改或覆盖历史 artifact；不要把 `V19-OD-00-PRECHECK` 当作实现依据。
- 设计规范使用 `design-system/tokens.css` 与 `DESIGN.md`；当前模式为 `PROJECT_EMBEDDED`，不是平台已激活。

## 2. 推荐 React 分层

```text
app/
  routes/              路由、懒加载、权限边界
  shell/               AppShell、顶栏、抽屉、移动底栏
features/
  auth/ people/ rules/ sources/ attendance/ self-service/ access-ops/
components/
  states/ tables/ forms/ dialogs/ import-wizard/ evidence/ audit/
domain/
  permissions/ rules/ batches/ attendance-events/ time-accounts/
```

不得把所有 artifact 合并成单一巨型页面；同一 HTML artifact 内的标签页可在 React 中拆成子路由或受控子视图。

## 3. 路由与上下文

- 统一上下文键：`role`、`month`、`department`、`employee`、`batch`、`filter`、`return`。
- 正式实现不能相信客户端传入的角色或范围；每次路由和数据请求都由服务端鉴权。
- 切换角色、组织、员工或期间时先清空旧范围数据，再渲染新范围；禁止短暂闪现上一范围内容。
- 返回来源页时保留筛选与批次上下文；未知 route 返回统一 404，未授权返回统一 403。
- `/display/attendance` 是独立只读大屏，不进入普通产品导航；`/qa/handoff` 仅为设计交接，不进入生产路由。

## 4. 状态与数据管理

- `shenzhou-hr-v19-demo-state` 和 `PROTOTYPE_ONLY` 控制条只用于原型，生产不得实施。
- 建议把服务端查询缓存与客户端表单草稿分离；高风险操作完成后按受影响 key 精确失效。
- 上传、预检、发布、作废/冲正、重算、月结、反月结和导出必须使用不同 mutation 与权限点。
- 批次、规则版本、原始行、规范事件、异常、重算和月结都保留服务端状态机与审计时间线。

## 5. 三类 Excel 导入

- 组织/员工期初、时间账户期初、离线原始打卡必须是三个独立 feature、route、模板和权限域。
- 浏览器只负责文件选择与交互；解析、病毒扫描、对象存储、幂等和发布事务在服务端完成。
- 预校验不得写入正式数据；发布前展示范围、记录数、期间、影响和可逆性。
- 离线打卡只接收原始事实，不接收迟到、早退、缺卡、旷工或加班时长等计算结果。
- API/Excel 跨来源重复仍保留两份原始证据，并生成可追溯的规范事件关联。

## 6. 规则、冻结与解释

- 规则模型包含模板、版本、草稿/校验/发布/停用、作用范围、生效期、优先级、冲突、试算、审计和回滚。
- 新规则不能静默改写冻结或已月结期间；任何历史变更都需要显式重开、重算与审计流程。
- 结果解释统一输出：输入事实、规则版本、计算过程、结果、下一步。
- 晚餐、迟到宽限、单边缺卡、假别和年假默认值来自正式后端配置，不得在组件内硬编码为不可变常量。

## 7. 权限与隐私

- 权限域至少隔离 ATTENDANCE、LEAVE、LOCATION、PAYROLL、AUDIT；默认拒绝。
- 菜单隐藏不是鉴权。查看、编辑、上传、预检、发布、下载错误报告、作废、查看原始文件/行、重算、月结、反月结和导出分别授权。
- 系统管理员默认不能查看业务敏感明细；审计员只读。
- 导出前显示范围、敏感字段、用途并记录审计。
- 当前前端不得出现薪资或工资条的导航、route、搜索、通知、报表、员工入口或“暂未开放”页。

## 8. 响应式与无障碍

- PC 以 1366px 为最低高密度验收宽度；平板导航使用抽屉；720px 以下表格改为字段标签卡片。
- 移动端仅承载员工自助和轻量任务，底栏固定为今日、记录、反馈、我的。
- 所有交互目标至少 44×44px；键盘可完成登录、导航、筛选、详情、保存草稿与取消。
- 对话框设置焦点陷阱、Escape 关闭、关闭后恢复触发控件焦点；错误与字段使用 `aria-describedby` 关联。
- 状态、图表和选择不得只靠颜色；支持 `prefers-reduced-motion`。

## 9. 大屏实施

- 使用 1920×1080 逻辑画布等比缩放到 3840×2160；不要为 4K 建立第二套布局。
- 仅展示授权聚合，不下钻个人，不包含精确位置、假别原因或敏感单据内容。
- 服务端返回指标值、口径版本、源水位、展示刷新时间和范围；前端不得把本地时钟冒充源水位。

## 10. 测试门禁

- 单元测试：权限映射、状态机、口径格式、上下文序列化。
- 组件测试：键盘、焦点陷阱、字段错误、危险确认、状态层。
- 集成测试：五条 `demo-flow` 的生产等价路径、冻结保护、批次幂等、返回上下文。
- E2E：桌面、平板、手机和 1920/4K 大屏目标；无未登记路由和无死链。
- 安全、接口、性能、数据库隔离、外部来源真实性保持 `NOT_VERIFIED`，必须由专项测试关闭。
