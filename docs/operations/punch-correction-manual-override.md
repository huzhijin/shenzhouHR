# 补卡配额与 HR 人工例外处理

## 标准流程

1. 员工通过 `POST /api/attendance/punch-corrections` 提交补卡日期、方向和原因。
2. 系统以自然月为单位校验配额；`PENDING` 与 `APPROVED` 均占用当月唯一一次配额，`REJECTED` 与 `CANCELLED` 不占用。
3. HR 核对排班、原始打卡和说明后，通过 `PUT /api/attendance/punch-corrections/{id}/approve` 批准。
4. 只有 `APPROVED` 申请可作为合成打卡证据进入考勤重算；待审批申请不改变缺卡数。

## 允许的例外处理

- 员工误填日期或方向：HR 拒绝原申请；拒绝状态释放该月配额，员工重新提交正确申请。
- 重复或无效申请：HR 拒绝并在审批备注中写明原因，不得直接修改数据库状态。
- 源设备或 OA 批量故障：由 HR 发起有工单号的考勤调整，记录员工、业务日、补卡方向、证据附件、审批人和调整原因；调整必须走重算和审计链。
- 已批准申请确需撤销：创建新的反向调整/更正记录，引用原申请 ID；不得覆盖或删除原记录。

## 禁止事项

- 不得通过 SQL 删除 `PENDING`/`APPROVED` 记录以恢复配额。
- 不得把 `REJECTED` 临时改为 `APPROVED` 绕过审批接口。
- 不得为未来日期、上月以前日期、非工作日或免打卡岗位提交补卡。
- 不得将人工补卡伪装成得力设备原始打卡；合成证据必须保留申请 ID 和审批信息。

## 审计与复核

人工例外工单至少保留：申请 ID、员工、业务日、补卡方向、原始证据、审批备注、审批人、审批时间、重算批次和前后结果摘要。月结前由 HR 复核所有例外工单，确认合成证据数与批准申请数一致。
