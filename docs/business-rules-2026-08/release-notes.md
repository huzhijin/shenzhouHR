# 2026-08 考勤业务规则对齐候选发布说明

**发布状态：待部署。** 本说明描述目标发布口径，不代表已经完成 OpenSpec 12.9～12.12 的排期、预发布、生产部署、24 小时观察或一个月稳定运行。

业务和验收基线为 [OpenSpec change](../../openspec/changes/business-rules-alignment-2026-08/proposal.md)，业务来源为[客户业务决策签字稿](../../.umadev/explore/FINAL-BUSINESS-DECISIONS-SIGNOFF.md)。

## 核心变化

### 出勤率改为天数口径

个人和部门出勤率统一使用：

```text
实际出勤天数 ÷ 应出勤天数 × 100%
```

- 结果四舍五入到 2 位小数。
- 应出勤天数为 0 时显示 `N/A`，不得除零。
- 部门汇总使用 `SUM(actualAttendanceDays) / SUM(scheduledAttendanceDays)`，不是员工百分比的简单平均。
- 部门汇总排除应出勤天数为 0 的员工，并严格限制公司边界。
- 新口径只从发布切换后向前使用，不自动回填历史月份；切换前后的出勤率不宜直接同比。

示例：22 个应出勤日、20 个正常打卡日、2 个已批准年假日，实际出勤天数为 22，出勤率为 `100.00%`。

### 新增或明确的业务规则

| 领域 | 发布口径 |
|---|---|
| 带薪假 | 年假、调休、病假、婚假、产假、陪产假、丧假、工伤假、孕检/哺乳假计实际出勤；事假不计实际出勤。带薪假仍保留在分母。病假在报表单独展示。 |
| 迟到转旷班 | 先扣适用宽限时间，再以有效迟到分钟判断；有效迟到 `>= 30` 分钟转为旷班，不计实际出勤，迟到分钟归零，旷班分钟为适用排班工作段的全部分钟。30 分钟阈值固定不可配置。 |
| 补卡 | 每名员工每个自然月一次申请；`PENDING`、`APPROVED` 占配额，`REJECTED`、`CANCELLED` 不占；只允许本月或上月的有效工作日，禁止未来日期和免打卡岗位；批准后才进入计算。 |
| 加班 | 读取 `formson_0172.field0096`，分为计薪、转调休、义务三类并显示汇总；空值或未知枚举隔离，不计入任何分钟数。 |
| 免打卡 | 已批准免打卡单据无需打卡即可计出勤，日期范围包含结束日。 |
| 外出 | 只有“已批准外出单据 + 有效打卡”同时存在才计出勤；有单无卡按缺勤处理。 |
| 出差 | 不查询出差单据，按普通工作日的打卡要求处理。 |
| 缺卡 | 标准单工作段全天无卡为 2 次缺卡；仅缺一侧为 1 次；完整免打卡不产生缺卡；部分免打卡按未豁免侧计数。 |
| 得力同步 | 每小时整点执行；记录时间、数量、成功/失败和错误；保留至少 30 天；失败不推进最后成功水位；不提供红黄灯、不设延迟阈值、不阻断月结。 |
| 调岗 | 按考勤发生时有效任职部门分配，调岗月按部门期间拆行；各行合计不得重复或丢失考勤天数。 |

## API 变化

补卡接口的完整请求、响应、权限和错误合同见 [OpenAPI](../../api/openapi.yaml)。运行时主路径为：

- `POST /api/v1/attendance/punch-corrections`（同时兼容 `/apply`）
- `GET /api/v1/attendance/punch-corrections/quota?employeeId={id}&month={yyyy-MM}`
- `GET /api/v1/attendance/punch-corrections/quota/{employeeId}/{month}`
- `PUT /api/v1/attendance/punch-corrections/{requestId}/approve`

`/api/v1/attendance/punch-supplement` 保留相同操作的业务术语兼容入口；未版本化 `/api/attendance/...` 仅用于现有客户端兼容。所有接口使用现有安全会话和 CSRF 防护，并按 `ATTENDANCE_PUNCH_CORRECTION:*` capability 授权；提交、配额查询和审批还会调用 `PeopleRepository.canAccessEmployee`，按对应业务日期校验 `COMPANY`、`ORGANIZATION` 或 `SELF` 员工范围。

## 数据库变化

早期草案曾以 V32 作为占位编号；现 OpenSpec、迁移文件和部署文档均统一使用 `V48`。V48 新增补卡申请、OA 枚举映射、得力同步日志，补充假别和三类加班字段，并建立补卡 capability。详见 [V48 数据库结构说明](database-schema-v48.md)。

## 已知兼容性影响

- 分钟仍用于工时、迟到和旷班罚时，但不再用于出勤率。
- 同一员工在调岗月可能从一行变为多行，报表消费者不得再假设“员工每月只有一行”。
- 新增报表字段和补卡 API 需要客户端按 OpenAPI 更新；未知响应字段应按客户端兼容策略处理。
- 当前实现没有名为 `businessRules2026_08` 的运行时总开关。若需撤销业务逻辑，应回退应用制品；不得假定可通过一个未实现的 feature flag 切回旧公式。
- 已发布历史投影不得被静默覆写。任何重算或重新发布必须保留版本、原因和审计链。
- OA 销假尚未具备原单关联、0..N 当前集合、系统扣减/返还小时和一致水位的完整生产链；遇到有效 `LEAVE_REVOCATION` 时本版显式失败关闭，不会静默忽略或继续发布错误请假结果。
