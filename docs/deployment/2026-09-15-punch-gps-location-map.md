# 手机打卡查看位置（2026-09-15）

得力 GPS / 外勤卡开始保存地址和原始经纬度。人事在考勤日报详情、考勤明细列表点进某一次打卡查看位置。坐标系未确认前不画点。

## 部署

1. 发后端（Flyway **V69、V70**）+ 前端。
2. **不要** `checkin_query_init`，不要回拨得力水位。
3. 新同步的 GPS 卡才会带地点。已经入库、当时没存坐标的历史卡**不回放**。
4. 底图密钥可选，写在 `/etc/shenzhouhr/shenzhouhr.env`，不要进仓库：

```
SHENZHOUHR_MAP_BASEMAP_PROVIDER=AMAP
SHENZHOUHR_MAP_BASEMAP_KEY=
```

当前实现支持 **AMAP（高德 Web 服务 API Key）**。未配置、供应商不支持、转换失败、超时或图片加载失败时仍可看地址文字，抽屉显示「地图暂不可用」。后端出站需要允许 `https://restapi.amap.com`。

对于已验证且成功转换为 WGS84 的地图点，后端先使用高德坐标转换接口转换，再获取一张包含一个标记的 600×360 静态地图。每个外部请求最多等待3秒，不重试；密钥和供应商 URL 不传到浏览器，也不写入普通日志。浏览器只收到内嵌 PNG，不需要放宽现有 CSP。地图不会绘制轨迹。

参考：[高德坐标转换](https://lbs.amap.com/api/webservice/guide/api/convert)、[高德静态地图](https://lbs.amap.com/api/webservice/guide/api/staticmaps)。

当前适配器把得力坐标标成 `UNKNOWN`，即使填了密钥也不会画点，避免当 WGS84 画偏。确认得力是 GCJ-02 后再打开转换。

## 权限

V69 给 `HR_ADMIN`、`EXECUTIVE`、`DEPARTMENT_HEAD`、`MANUFACTURING_CENTER_SUPERVISOR`、`EMPLOYEE_SELF`、`SYSTEM_ADMIN` 补 `ATTENDANCE_LOCATION:READ`（已有则跳过）。

管理者查看要填2至500字原因，并按 `ATTENDANCE_LOCATION:READ` **自身授权的人员范围**校验。报表查询权限不能扩大位置权限范围。

员工在「我的考勤 → 每日记录 → 查看打卡」看自己的卡，不填原因；只需 `ATTENDANCE_SELF:READ`，不需要报表查询权限。本人日卡接口为 `GET /api/v1/me/attendance/day-punches?businessDate=YYYY-MM-DD`，后端从登录身份确定人员，不接受客户端切换员工。

每次已登录位置请求的成功、缺权限、超范围、原因不合法、事实不存在或已失效均记录 `PUNCH_LOCATION_READ`。V70 扩大审计原因列，位置审计记录 `employeeId=...; reason=...`，保存完整原因；其他审计的原有64字应用限制不变。未知或已失效事实没有可确认的员工，不记录猜测的员工归属。

## 验收

1. 同步一笔新的手机打卡后，考勤日报点开该人该日，列表有「手机」和「考勤机」。
2. 有位置权限的人点「查看位置」，填原因，看到地址，**没有**经纬度数字，并显示「地图暂不可用」。
3. 无目标员工位置权限的人看不到「查看位置」；本人自助查看例外。
4. 导出考勤日报 Excel 不含地点或坐标。
5. 大连日历仍按 `docs/deployment/2026-09-15-dalian-holiday-calendar.md` 单独配置，与本功能无关。

## 审查修复后的补充验收

- 只有本人位置权限、却有全公司报表权限的用户，不能查看同事位置。
- 打卡人员从甲纠正为乙后，只按当前激活事件中的乙授权；旧关联不再参与本人或范围判断。撤销后接口不返回位置。
- 本人只有 `ATTENDANCE_SELF:READ` 时可查看自己当天各次打卡；请求同事事实ID返回403。
- 用测试数据库中已验证的 WGS84 地图点检查真实单点图片、供应商失败及浏览器图片解码失败的地址降级；禁止为验收随意修改生产 UNKNOWN 坐标状态。
- 核对审计中的 actor、fact id、employee id、完整原因及结果；普通日志不输出地址、坐标、密钥。
