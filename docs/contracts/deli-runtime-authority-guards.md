# 得力正式同步运行时权威守卫

## 结论

正式得力同步现在具备且仅具备一个生产
`AttendanceConfigurationResolverPort` 和一个生产
`AttendancePeriodProtectionPort` 实现。两个实现都只读取现有权威事实，
不根据当前日期、默认法人或任意第一行推断可写状态。

## 考勤配置解析

配置解析以打卡时刻为输入，覆盖所有 IANA 时区可能对应的本地日期，
并在本地时间早于 `06:00` 时同时校验前一业务日。每个候选业务日必须
唯一解析以下完整链路：

1. 有效法人、员工版本、当前任职版本及有效组织；
2. 生效且未被 successor 覆盖的员工考勤组分配；
3. 已激活的考勤组 revision 与地点 revision；
4. 已发布且覆盖业务日的工作日历版本及唯一日历日；
5. 当日日历覆盖班次，或考勤组默认班次的唯一已发布版本。

地点、日历和班次时区必须完全一致，所有对象必须属于请求法人。跨日
候选若发生当前端口无法表达的员工、任职、分配、考勤组、地点或班次
切换，解析结果为 `authoritative=false`，同步安全失败，不选择任意一侧。
解析摘要包含两个候选日的全部版本标识和 snapshot digest；日历日、
班次或配置版本变化都会改变摘要。

## 期间保护

期间保护只接受覆盖业务日的最新 `PUBLISHED`
`attendance_report_projection`：

- `OPEN`：允许写入有效事件和重算意图；
- `REOPENED`：允许经权威重开后的写入和重算；
- `FROZEN`、`CLOSED`：阻断；
- 不存在已发布 projection、草稿、身份/任职不唯一或存储内容非法：
  返回 `UNKNOWN` 并阻断。

因此，每个要接收正式得力数据的法人和期间必须先通过内部可信发布边界
发布明确的 `OPEN` projection。系统不会把“当前月”自动视为开放，也没有
新增可绕过发布校验的公开开关或重开接口。

两个权威查询均使用参数化 SQL 和 `FOR SHARE`。它们在得力单页
`REQUIRES_NEW` 事务内持有共享锁直到有效事件与重算意图提交；V10
projection 发布器先对同一法人加排他锁，因此正式发布路径上的关闭/冻结
不能与已通过检查的同步写入穿插。运维与数据修复不得绕过应用发布器直接
修改 projection 状态。
