## 3. 九类现有报表代码复核

| 报表 | 当前实现 | 不得忽略的差距 |
| --- | --- | --- |
| 考勤明细 | 从员工日事实展示应出勤、确认工作、认可加班、请假、旷工、迟到、早退、缺卡及首末打卡 | 日事实的生产存储、完整性门禁和每日自动发布未闭环 |
| 请假统计 | 筛选生效 OA 单据并按所选月份的时间区间判断是否重叠 | 跨月单据目前展示整单认可分钟，不能在未确认分摊事实前宣称为月度准确值 |
| 加班统计 | 按发生时组织和员工汇总工作日、周六、周日、法定节假日认可加班 | 依赖审批区间、打卡证据、日历和餐扣规则均已正确形成事实 |
| 月工时统计 | 汇总应出勤、确认工作、加班、请假、旷工和实际工作 | 尚无服务端合计行、部门/班组/公司多层汇总产品 |
| 异常总览 | 展示 stable case 当前状态和安全证据摘要，并可按状态筛选 | 异常 current state 的生产持久化和复核闭环未完成 |
| 迟到统计 | 员工日迟到分钟大于 0 时当前累计一次，并保留原始/计罚分钟 | 同日多班段和事件级次数口径待确认 |
| 未打卡统计 | 汇总日事实中明确缺失的打卡次数 | 全天无卡按一次还是上下班两次等口径待确认 |
| 出勤率统计 | 暂行代码为排班内确认工作分钟 ÷ 原始应出勤分钟 × 100 | 与历史正式口径及 V30 文本冲突，签字前不得作为正式薪资或管理指标 |
| 年假统计 | 从不可变时间账户事实展示期初、发放、转入、增减、使用、到期、返还和余额 | 期初导入、正式账本持久化及月度 snapshot 尚未交付 |

## 4. 与最初需求相比仍未完成的报表能力

以下项目不能仅通过填入几行数据补齐，需要继续实现或由客户明确从首期范围移除：

1. 独立的员工逐日日报、自然周周报、员工月报、部门/班组月汇总和公司月汇总；
2. 报表页的授权组织树、员工搜索、考勤组筛选及明确的“包含下级组织”交互；
3. 公司综合工作台中的出勤率、异常率、确认工时、认可加班、请假、未月结、来源新鲜度、趋势和部门比较；
4. 个人日/周/月记录及假期余额的生产网关；
5. 早退、旷工、出差/外出、补签/人工调整和月结差异是独立报表还是组合筛选；
6. 每类报表的最终列顺序、合计行、单位、小数、空值和默认排序；
7. 大数据量的数据库侧或预聚合分页。目前计算器会先读取授权月份事实、在 Java 内聚合，再截取当前页；
8. 投影发布前对人员日覆盖、来源水位、输入/规则/账户版本及错误异常的强制完整性校验；
9. 报表发布、重算、日更、月结、关闭后差异版本和失败告警的可运行编排；
10. 真实 MySQL、真实得力租户、真实 OA 只读库及客户最终代理环境的端到端对账证据。

## 5. 必须由业务方确认的口径

完整选项和建议见报表业务口径确认单，至少需要确认以下内容后才能继续收口公式与验收用例：

1. 出勤率分子、分母、带薪/非带薪假、外出/出差、零分母、是否封顶及组织汇总权重；
2. 异常率的分子、分母、状态范围及同一员工日多异常是否去重；
3. 迟到和缺卡的“次数”单位，以及全天无卡和模糊打卡如何计数；
4. 开放月能否发布暂算投影、日更频率、来源新鲜度阈值和关闭版完整性门禁；
5. 日报、周报、月报、部门/班组/公司汇总的首期范围与生成截止时间；
6. 跨月请假/调休按月分摊规则、销假/撤回链及假别展示顺序；
7. 年假/调休余额的历史时点、二次入职/跨公司账户、到期和 8 小时等价天数口径；
8. 报表字段、合计行、默认排序、导出角色、用途、留存和传递要求；
9. 完整管理工作台和正式大屏是否属于首期，以及小样本抑制阈值；
10. 高管、HR、部门负责人、普通员工、审计和系统管理员的最终数据范围矩阵。

## 6. 安全与上线结论

- 不在代码、文档、命令行或 Git 中保存得力 Secret、OA 密码、数据库密码、Cookie 或客户明细数据；
- OA 必须使用最小只读账号和固定白名单查询，不能把可编辑 SQL 交给页面；
- 任何无法唯一匹配员工、公司、地点、时区、单据版本或期间的来源记录必须隔离，不能静默丢弃或猜测；
- 缺失事实必须显示“数据未准备好/部分数据”，不能以数值 0 伪装；
- 自动化测试通过只证明代码合同未回归，不替代客户真实数据、人工金标准、容量、恢复和浏览器验收。

因此，本次提交的正确交付定义是：修正已确定的软件缺陷，冻结并公开剩余业务选择，补齐客户说明和
上线门禁；在客户完成确认且上游生产链闭环前，不把首页和各种报表标记为生产就绪。
