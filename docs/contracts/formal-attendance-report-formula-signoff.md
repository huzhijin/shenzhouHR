# 正式考勤报表计算口径与待确认项

基线：`神州HR考勤与薪资核算系统_PRD_V1.9.docx`

日期：2026-07-29

本文只记录真实取数与计算口径，不包含演示数据。

## 1. 目标数据链路与当前实现边界

```text
得力 E+ 原始打卡
        +
OA 已批准业务单据
        +
员工/发生时组织版本、考勤组、班次、工作日历、政策版本
        ↓
标准化证据与隔离区
        ↓
按工作段确定性计算（日结果 + stable exception case）
        ↓
不可变月度报表投影
        ↓
9 张正式报表及受控 XLSX 导出
```

来源原始记录不可变；同一来源 ID 与来源实例按幂等键处理。未知审批状态、人员无法唯一匹配、重复/重叠、时间逆序、来源结构变化等记录进入隔离或异常，不作为有效出勤证据。

该图是正式目标链路，不代表当前已经端到端自动运行。得力分页同步及其权威考勤配置/期间保护适配器、OA 静态映射与只读人员目录、计算域、不可变报表投影及查询/导出边界已经实现；OA 六类业务查询、正式输入快照装配、日结果持久化和月结发布编排仍受本文第 6 节合同/适配器阻断，并保持 fail closed。得力同步只有在目标公司已发布完整配置时间线且目标期间已有明确 `OPEN` 或 `REOPENED` 投影时才允许写入；缺失或歧义一律阻断。

证据优先级为：

1. HR 已批准调整；
2. 撤销/销假；
3. OA 已批准业务单据；
4. 得力原始打卡；
5. 系统异常候选。

时间统一解释为 `Asia/Shanghai`，计算区间使用半开区间 `[start, end)`。

## 2. 日计算指标

| 符号 | 已实现口径 |
| --- | --- |
| `S` 应出勤分钟 | 班次工作段分钟；不含休息、认可加班和自然日请假 |
| `W_in` 排班内确认工作分钟 | 排班内有效打卡，或有效外出/出差/免打卡证据覆盖的分钟；请假不算工作 |
| `E` 延长在岗分钟 | 计划外在岗证据，仅用于判断候选，不直接等于认可加班 |
| `O` 认可加班分钟 | 计划外实际证据与已批准 OA 加班区间的交集，再扣除适用餐休 |
| `L` 请假/调休分钟 | 已批准请假/调休区间与排班工作段的交集 |
| `A` 旷工分钟 | 处理期限后，排班工作段中无工作且无有效覆盖证据的分钟 |
| 实际工作分钟 | `W_in + O`；加班转调休只入一次，不重复计入实际工作 |

迟到为计划开始到首次有效到岗之间未被有效证据覆盖的分钟；早退为最后有效离岗到计划结束之间未被覆盖的分钟。

默认月内第一次 `0 < 迟到 <= 15 分钟` 保留原始迟到分钟，但计罚迟到分钟为 0。单边缺卡默认等待 7 个自然日；超期后默认只将受影响工作段判为缺勤。

跨日班次默认归属截止为次日 06:00；无法唯一归属时形成阻断异常，不猜测工作日。

## 3. 工作日、周六、周日与节假日扣减

加班内部以分钟计算，展示保留 0.01 小时：

- 工作日：实际证据与已批准加班区间取交集；完整覆盖晚餐 `18:00–18:30` 时扣 30 分钟。
- 周六：使用周六独立规则；完整覆盖午餐窗口时扣周六午餐分钟，完整覆盖晚餐窗口时再扣周六晚餐分钟。
- 周日：使用周日独立规则；完整覆盖午餐窗口时扣周日午餐分钟，完整覆盖晚餐窗口时再扣周日晚餐分钟。
- 法定节假日：按节假日独立日型，午餐和晚餐均可单独配置；旧策略未配置节假日晚餐覆盖时只回退工作日晚餐规则，不继承自然周六/周日规则。
- 调休工作日按 `ADJUSTED_WORKDAY` 进入工作日口径，不按自然周末直接判断。

扣减窗口、分钟及每个餐窗的触发门槛是版本化考勤组策略配置。周六、周日和法定节假日的午餐/晚餐参数分别以完整四字段组发布，不能只配置其中一部分。打卡先严格配对为连续在岗区间；只有同一连续区间完整覆盖对应餐窗，且当日已配对实际在岗分钟达到该窗门槛时才扣减。离场后再次进入形成两个区间，不能跨空档拼成“完整覆盖”，也不能按“当天有加班”直接固定扣除。

## 4. 九张正式报表

| 报表代码 | 主要事实来源 | 公式/边界 |
| --- | --- | --- |
| `ATTENDANCE_DETAIL` | 日结果 | 展示 `S/W_in/O/L/A`、实际工作、迟到/早退/缺卡和首末有效打卡 |
| `LEAVE` | OA 单据投影 | 只包含生效状态；按与月份重叠的半开区间纳入，跨月不漏单 |
| `OVERTIME` | 日结果 | 按工作日、周六、周日、法定节假日分别汇总认可加班 |
| `WORK_HOURS` | 日结果 | 实际工作 = 排班内确认工作 + 认可加班 |
| `EXCEPTIONS` | stable exception current state | 同一 stable case 只计一次，只返回安全摘要 |
| `LATE` | 日结果 | 同时汇总事件数、原始迟到分钟、计罚迟到分钟 |
| `MISSED_PUNCH` | 日结果 | 汇总单边缺卡次数；待补正与超期状态由异常报表承载 |
| `ATTENDANCE_RATE` | 日结果 | 暂行 `W_in / S × 100%`，`S=0` 显示 `N/A` |
| `ANNUAL_LEAVE` | 不可变时间账户台账 | 期初 + 系统发放 + 加班转入 + 人工增加 - 使用 - 到期 + 撤销返还 - 人工扣减 |

员工月内调岗时，汇总按员工和发生时组织版本拆分；不会把调岗后的事实并回月初部门。报表访问权限仍按查询时的当前有效授权范围解析。

## 5. 数据权限

当前角色边界：

- 公司 HR：必须同时拥有报表能力和公司数据范围，可查看该公司授权数据。
- 高管：必须显式授予报表能力和相应公司/组织数据范围；角色名称本身不构成授权。
- 部门负责人：按查询时员工的当前有效任职，只查看被授予组织及其当前后代组织；员工调岗后，原部门负责人不再因历史发生组织继续看到该员工明细。
- 员工本人：只查看会话绑定员工。

请求中的 `companyId`、`organizationId`、`employeeId` 和状态只能缩小服务端已授权集合。公司目录只返回当前主体有权访问且指定月份存在已发布正式投影的公司；单公司可自动选中，多公司必须显式选择，未选择时不查询或导出。四类报表事实均在 SQL 层同时绑定精确投影与精确公司，并应用同一个能力、主体、角色有效期、数据范围和当前任职谓词，再进行 Java 聚合、排序和分页。事实仍保存发生时组织用于展示与汇总，但发生时组织不扩大负责人当前可见人员集合；组织已停用、缺失当前组织投影或员工已调动时，不沿用历史范围放行。`SYSTEM_ADMIN` 没有隐式报表读取能力。

角色授权本身也受数据范围保护：服务端在同一事务中锁定授权人的当前有效授权，禁止给自己修改角色；授权人的 `ROLE:ASSIGN` 范围和有效期必须完整覆盖每一条目标授权，目标公司/组织必须存在且组织闭包属于授权人范围。员工本人角色只能使用 `SELF`，部门负责人只能使用 `ORGANIZATION`，公司 HR 使用明确 `COMPANY`，高管只能使用明确 `COMPANY` 或 `ORGANIZATION`。前端选择器只提供辅助约束，不作为安全边界。

导出与页面使用同一字段白名单和查询指纹。5 万行以内同步生成，超过 5 万行进入异步队列。创建、下载分别做能力检查和密码复核；下载时重新解析当前范围，计算包含投影、范围、筛选、最终行及底层事实/员工身份的精确可见内容摘要，并校验任务归属、公式、有效期、长度和 SHA-256。密码复核提交后，最终 capability、范围、当前任职、摘要和 BLOB 读取在同一 MySQL/InnoDB `SERIALIZABLE` 短事务内完成；撤权、人员等量调动或事实替换后旧文件不可取。

## 6. 需要业务/OA 联调确认

以下项目保持 `NOT_VERIFIED` 或“暂行”，不会以猜测值进入有效事实：

1. 出勤率最终公式：分子是否仍为 `W_in`；已批准请假是否从分母 `S` 扣除；组织/公司出勤率是否按分钟加权或按人员/天平均。
2. OA 各表真实审批状态列、最终批准/撤回/拒绝值、业务主键、修改水位及撤销版本链。
3. `formmain_0171/0251/0201/0203` 与各 `formson_*` 的真实主从关联列；`formmain_id` 目前只是假设候选。
4. OA `DATETIME` 的确切时区；免打卡 `DATE_RANGE` 结束日是包含还是不包含。
5. 请假类别 `field0089`、加班类别 `field0096`、补卡类型 `field0134` 的完整封闭枚举。
6. 出差/外出是否必须同时具备另一张配套单据，以及缺地点/事由时的最终处置。
7. 得力租户是否已经执行过一次初始化命令；初始化具有外部状态影响，未获明确授权前不由系统自动调用。
8. 周六与周日的最终午餐/晚餐窗口和扣减分钟。当前能力已支持分别配置；具体值需业务确认后发布策略版本。
9. 正式报表最终列顺序、显示名称及组织级出勤率/异常率驾驶舱的精确汇总公式。
10. 仓库仍缺正式 `AttendanceInputSnapshotAssembler`、日计算版本存储适配器和月结编排实现；当前餐扣的版本化配置、正式计算规则转换、连续在岗判定和确定性计算已具备，但在这些上游完成前不能声称生产任务已自动出数。

OA 数据源提供后，应按
[`oa-attendance-form-mapping-signoff-matrix.md`](./oa-attendance-form-mapping-signoff-matrix.md)
逐项完成只读 metadata、脱敏样本、状态/枚举和跨范围负例签字，之后才启用 OA 有效证据。
