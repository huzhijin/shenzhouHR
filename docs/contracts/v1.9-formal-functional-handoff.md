## 1. 已实现的正式能力

### 1.1 得力 E+ 打卡接入

- 凭据只从环境变量或外部密钥引用读取；仓库模板不包含实际 key/secret。
- 来源实例必须绑定明确公司，且按来源实例维护独立水位。
- 按官方 `next_id` 整数游标分页；请求不自行递增，响应游标原值以十进制文本持久化，并检测相同游标或已见游标循环。
- 整页原始事实、标准化记录、匹配/隔离结果、同步页记录和水位 CAS 在同一事务提交。
- 鉴权、协议、响应过大等永久失败不重试；限流、服务端错误、官方临时错误和传输故障最多重试三次。
- 原始 `check_data` 不进入日志、审计和报表；只保存允许的摘要与来源引用。
- 未找到唯一人员、配置、考勤期间保护或来源合同不满足时 fail closed，不把记录作为有效打卡。
- 正式运行时只有一个考勤配置解析器：从已发布的考勤组、地点、日历、日历日和班次版本解析打卡日及凌晨跨日候选；缺失、歧义、跨公司或时区不一致时不猜测配置。
- 正式运行时只有一个期间保护实现：只信任覆盖业务日的最新 `PUBLISHED` 报表投影；仅 `OPEN`、`REOPENED` 可写，`FROZEN`、`CLOSED`、`UNKNOWN` 均阻断。

### 1.2 OA 六类考勤单据边界

- 已冻结出差、请假、加班、外出、免打卡、补签共 10 张截图声明表的静态表/列白名单。
- 已实现独立、默认关闭的 OA MySQL 只读数据源骨架。
- 人员选人字段只允许单个 ASCII 正整数，并通过固定参数 SQL
  `SELECT id, code FROM org_member WHERE id = ?` 查询。
- 查询必须恰好返回一行；`org_member.code` 按原值匹配内部工号，不 trim、不改大小写、不转数值。
- 表单工号只作逐字节一致性核验；零行、多行、空 code、ID 回传不一致或工号不一致全部隔离。
- 审批状态、撤销版本、主从键、枚举、时区或日期边界未签字前，业务行不能成为有效考勤证据。

### 1.3 考勤计算与周末差异扣减

- 计算使用半开区间和版本化配置快照，原始事实不改写。
- 工作日、周六、周日、法定节假日分别解析餐扣规则；调休工作日以权威日历日型为准。
- 周六、周日及法定节假日可分别配置午餐/晚餐窗口、扣减分钟和触发门槛；旧策略未配置节假日晚餐覆盖时只回退工作日晚餐规则，不继承自然周末规则。
- ENTRY/EXIT 严格配对为连续在岗区间；离场后重新进入不能跨空档拼接餐窗覆盖。
- 认可加班只取实际在岗与已批准加班单的交集；达到触发门槛且同一连续区间满足窗口覆盖时才扣减一次。
- 迟到、早退、待补卡、逾期缺卡、打卡归属歧义、证据冲突和缺少加班单等常用异常可由日计算直接产生。

### 1.4 正式报表与导出

- 已实现 `ATTENDANCE_DETAIL`、`LEAVE`、`OVERTIME`、`WORK_HOURS`、
  `EXCEPTIONS`、`LATE`、`MISSED_PUNCH`、`ATTENDANCE_RATE`、
  `ANNUAL_LEAVE` 九类正式报表。
- 报表读取不可变月度投影，不接受客户端提交计算事实。
- 已提供受信任的进程内投影发布入口；同公司、月份串行，事实写入和最终 `PUBLISHED` 状态在一个事务完成。
- 已提供按月份读取授权公司目录的正式接口；目录只返回当前主体有权访问且该月存在 `PUBLISHED` 投影的公司安全名称，不泄露未授权或未发布公司。
- 单公司时页面可安全自动选中；多公司时必须由用户显式选择 `companyId`，未选择时不发起报表查询或导出，也不默认取第一家公司。
- 查询先在 SQL 层按公司、当前有效任职、当前组织闭包或本人范围过滤，再聚合、排序和分页。
- 查询、同步/异步导出、任务状态和下载均绑定同一个精确 `companyId`；任何跨公司响应、任务或内容摘要不一致均 fail closed。
- 同步/异步 XLSX 均绑定投影、公式、查询指纹、字段白名单和精确可见内容摘要。
- 导出创建、异步完成、状态查询和下载都会重新核验当前权限与可见内容；人员等量调动、底层事实替换、撤权、投影变化、过期或文件校验失败都会使旧导出不可取。
- 密码复核后在新的短事务中完成最终授权、可见内容和 BLOB 读取，避免复用复核前的数据库快照。

### 1.5 数据权限

- 公司 HR：必须同时具有正式报表能力和明确公司范围。
- 高管：角色名称不自动放行，必须显式具有能力及相应公司/组织范围。
- 部门负责人：只查看被授予组织及其当前后代组织中、当前有效任职的员工。
- 员工本人：只使用服务端会话绑定的唯一员工，不接受客户端 employeeId 作为授权依据。
- 角色授予由服务端原子校验；禁止给自己扩权，授权人有效范围和有效期必须完整覆盖目标授权，角色与 `COMPANY`、`ORGANIZATION`、`SELF` 范围类型必须匹配。
- 账号列表、详情、状态、锁定/解锁、密码重置和角色替换分别绑定所需 capability；该 capability 与覆盖目标的数据范围必须来自同一条当前有效授权链，不能把公司 A 的管理能力与公司 B 的普通范围拼接使用。
- 请求中的公司、组织、员工、状态和期间只能缩小服务端已授权集合。
- 报表公司目录、事实查询和导出都重新解析当前能力、当前有效授权及当前组织/任职；组织已停用、当前组织投影缺失或员工已经调动时，不沿用历史组织范围放行。
- `SYSTEM_ADMIN` 不隐式获得正式考勤报表读取权限。
- 权限 A+B 已在本地自动化回归中全覆盖：A 为角色/能力与精确公司、组织或本人范围的同时成立；B 为当前有效任职、当前组织投影与目标公司的一致性。任一条件不满足即拒绝，不能把不同公司的能力和范围拼接放行。
- 考勤组分配的读、写、幂等、重叠检测、继任和时间线写入均强制员工与考勤组的 `company_id` 一致；跨公司考勤组分配会被拒绝。

### 1.6 V11 公司维度切换保护

- 执行 V11 迁移前必须停止相关写入并确认所有幂等事务中不存在
  `STARTED` 状态；只要仍有一条未完成事务，就必须中止迁移并先安全完成或处置，
  不允许带着在途事务强制切换。
- MySQL 8.4 对“带外键且表上存在已启用 CHECK 的列重命名”无法直接选择单一
  COPY/INPLACE 算法。V11 只在已停写并通过 exact V10 preflight 后，保存会话级
  `FOREIGN_KEY_CHECKS`、临时停用固定 44 个已审核 CHECK、以 INPLACE 完成 29
  个边界列重命名，随后立即恢复会话外键状态并重新启用同一 44 个 CHECK；latest
  gate 必须再次证明 28 张依赖表/29 条精确外键边、44/44 CHECK 已启用且零孤儿。
- V11 任一 DDL 中途失败时，必须丢弃该迁移连接并把 schema 视为 partial；
  禁止在 partial schema 上继续、重放或静默 Flyway `repair`。只能从已验证备份
  恢复，或重建明确授权的测试库后从 exact V10 重新执行。
- 隔离 MySQL 8.4.10 的 live7 回归已验证 V11 的 29 张边界表、28 张关系表、29
  条精确外键、44/44 已启用 CHECK 与 5 组旧索引到公司索引的切换；该结果仅证明
  受控隔离库迁移合同，不替代生产容量、恢复或真实外部数据验证。
- V10 及以前创建的报表导出任务，在 `COMPANY` 范围和可见内容摘要切换后必须
  安全失效并由用户重新创建；不得放宽状态/下载授权校验，不得改写历史查询指纹、
  可见内容摘要或把旧导出重新标记为可用。

### 1.7 V9 MySQL 8.4 保留字兼容修正

- 2026-07-29 在隔离 MySQL 8.4.10 的真实 V1→V10 迁移中，V9 首次执行在
  `punch_import_row.row_number` 处返回 SQL 1064；`ROW_NUMBER` 是 MySQL
  保留字。V9 因此从未在该验证环境成功上线。
- 修正仅为 V9 中该列声明、两个索引引用和 CHECK 引用增加标识符反引号，不改变
  表、列名或业务语义。V9 SHA-256 从
  `7855a44e2f6d066490db4b2259bf33903f295a7fe85232af3dac0c21d46ed3cd`
  有意更新为
  `56a0476ef24a6fd6ae8559f11b8ace4fdec274f6e1ce681c5525e8335dbd9150`。
- 这是对“尚未成功上线且不可执行的 migration”的兼容修正，不是常规历史
  migration 重写。任何外部数据库只要已有成功 V9 history，均禁止静默执行
  Flyway `repair`；必须先核对实际 V9 schema、已登记 checksum、备份和影响范围，
  经变更审批后选择明确的前向兼容方案。

## 3. OA 数据源到位后的执行顺序

1. 使用只读账号完成 metadata 和 GRANT 证明，不提供写权限。
2. 按
   [`oa-attendance-form-mapping-signoff-matrix.md`](./oa-attendance-form-mapping-signoff-matrix.md)
   逐项冻结物理合同。
3. 为每类表单实现独立固定投影 SQL；所有条件参数绑定，未知状态/枚举进入隔离。
4. 用脱敏的批准、撤回、拒绝、修改、补录、跨月、跨任职和 0/1/N 人员匹配样本做负向验收。
5. 先在影子同步中核对数量和摘要，再允许生成有效 OA 证据。
6. 完成计算输入装配和闭月发布编排后，才把报表状态从“内部发布入口就绪”提升为“自动出数就绪”。

- 免打卡结束日期是否包含；OA `DATETIME` 的权威时区。
- 请假、加班、补卡类型的完整原始值映射。
- 外出/出差缺少地点或事由时是阻断、警告还是允许补正。
- OA 区间跨任职/组织版本时拆分事实还是要求一个版本完整覆盖。
- 时间账户报表以哪一个不可变 snapshot/as-of 作为人员和组织版本锚点。
