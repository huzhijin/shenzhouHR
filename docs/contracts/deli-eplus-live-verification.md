文档基线：[得力 E+ 云考勤开放接口](http://doc.delicloud.com/v3/integration/oa.html)
`CHECKIN/checkin_query`

## 当前结果

- 官方 HTTPS 端点连通：通过。
- App Key/Secret 签名鉴权：通过。
- HTTP 状态：`200`。
- 厂商业务状态：`code = 0`。
- 首次安全探测：`next_id = 0`、`page_size = 1`，返回 0 条记录并提供后续游标字段。
- 原始打卡行、位置、设备内容和游标值未写入本文或日志。
- 未调用初始化命令，也未产生外部写入。

该结果证明凭据和只读查询链路可用，不证明租户历史数据完整、初始化已完成或正式同步水位正确。返回 0 条记录可能表示当前游标没有可见记录，也可能需要由租户管理员确认一次性初始化状态。

## 安全与运行边界

- 凭据只保存在被 Git 忽略、权限为 `0600` 的 `.env.deli.local`。
- 正式配置默认 `DELI_EPLUS_ENABLED=false`；显式启用后才装配客户端。
- 只允许官方 `https://v2-api.delicloud.com/v2.0/cloudappapi`，禁止重定向。
- 页大小范围为 1–500。按得力官方合同，`next_id` 是 JSON 整型；数据库以十进制文本保存以避免 64 位溢出，协议边界用任意精度整数编码。系统不自增、不推算顺序，非空页返回相同或已见游标时立即阻断循环。
- 响应有超时和最大字节数限制；异常只暴露安全错误码。
- 仅网络传输失败、HTTP 429/5xx、厂商 109（超时）和 110（超限）进入有上限重试；鉴权、签名、协议结构、字段校验和响应过大不盲目重试。
- `check_data` 只参与不可逆记录摘要，并在入账前丢弃原文；不进入报表。
- 后续正式同步必须从持久化 committed cursor 继续，并在成功提交整页证据后再推进游标。
