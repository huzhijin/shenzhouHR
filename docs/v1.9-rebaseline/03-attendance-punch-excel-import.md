# V1.9 需求补充｜离线考勤打卡 Excel 导入

> 基线地位：本文件由“当前明确要求”补充 PRD V1.9；发生冲突时按本轮事实优先级裁决。当前仅冻结产品、数据、API 和验收契约，不表示功能已实现。

## 1. 需求结论

系统新增“考勤打卡 Excel 导入”，用于无网络办公地点、暂时无法连接接口的设备、非得力或不同型号考勤机产生的原始打卡流水。

该功能导入的是“原始设备打卡事实”，不是批量补签，也不能直接导入迟到、早退、缺卡、旷工、加班时长等计算结果。所有来源统一进入：

`原始事实层 → 标准化与匹配层 → 有效打卡层 → 考勤计算层`

得力 API、设备 Excel 和 OA 考勤业务单据必须共享同一套证据链和考勤计算逻辑。

## 2. 适用场景

- 办公地点无网络，考勤机只能定期导出文件；
- 设备不是得力考勤机，暂时无法建设 API；
- 得力或其他设备暂时离线，需要导入设备本地导出的流水；
- 不同厂商文件字段不同，需要保存和复用字段映射方案。

不适用：员工忘记打卡后的人工补签。补签必须继续使用已确认的补签申请和证据流程，不得将人工数据伪装成设备打卡。

## 3. 用户与权限

主要用户为考勤管理员。上传、预检、发布、作废/冲正、查看原始文件、查看原始行、下载错误报告和触发重算必须分别鉴权，并受组织/地点数据范围限制。

审计员只读查看批次、原始事实、标准化结果和审计；系统管理员默认不能借技术角色读取员工考勤业务明细。

## 4. 标准流程

1. 选择来源类型、地点、设备、时区和已有字段映射方案；
2. 下载标准模板，或上传考勤机原始 `.xlsx`；
3. 完成字段映射和设备人员/员工匹配；
4. 预校验文件、时间、任职周期、权限、重复记录和冻结期间；
5. 展示总行数、有效、错误、完全重复、疑似重复、员工未匹配、设备未映射、冻结期间和可发布数量；
6. 下载错误报告并修正，或按权限确认警告；
7. 查看受影响员工、日期、组织和预计重算范围；
8. 二次确认后发布到原始事实层；
9. 开放期间仅重算受影响员工和日期；
10. 查看批次、原始行、规范事件、来源证据、重算结果和审计。

批次状态机（API 枚举与 UI 一一对应）：

`DRAFT → VALIDATING → AWAITING_CONFIRMATION → PUBLISHING → PUBLISHED / PARTIALLY_PUBLISHED / PUBLISH_FAILED → VOIDED`

- 预检存在阻断错误时进入 `VALIDATION_FAILED`；修正文件或映射后只能重新进入 `VALIDATING`，不能直接发布。
- 命中冻结/月结保护时进入 `BLOCKED_BY_FROZEN_PERIOD`；期间重开后必须重新预检，不能沿用旧确认。
- `PUBLISH_FAILED` 只表示发布事务未成功；不得与 `VALIDATION_FAILED` 混用，也不得产生已发布 raw fact。
- `VOIDED` 只能由已发布状态通过作废/冲正进入，不能恢复或物理删除证据。

## 5. 标准模板

已提供参考模板：

`outputs/attendance-import-template-v1/神州HR_考勤打卡导入模板_V1.0.xlsx`

工作表：

- `导入说明`；
- `考勤打卡导入`；
- `设备人员映射（可选）`；
- `字段说明`；
- `枚举值`；
- `示例数据`。

考勤打卡字段：

| 字段 | 必填 | 规则 |
|---|---:|---|
| 场地编码 | 是 | 必须匹配有权限且已启用的场地 |
| 设备厂商 | 否 | 用于来源识别和映射方案 |
| 设备型号 | 否 | 用于复用厂商/型号字段映射 |
| 设备编号 | 建议 | 参与设备人员绑定和幂等去重 |
| 设备人员编号 | 是 | 保留前导零；与设备/场地组合匹配员工 |
| 员工工号 | 建议 | 存在时优先精确匹配有效任职 |
| 员工姓名 | 否 | 仅人工核对，不能作为唯一匹配键 |
| 打卡时间 | 是 | Excel 日期时间，格式 `yyyy-mm-dd hh:mm:ss` |
| 打卡方向 | 否 | `AUTO/IN/OUT`，默认 `AUTO` |
| 验证方式 | 否 | `FACE/FINGERPRINT/CARD/PASSWORD/OTHER/UNKNOWN` |
| 原始记录 ID | 建议 | 来源范围内唯一时作为最高优先级幂等键 |
| 原始事件码 | 否 | 只保留来源证据，不直接决定考勤结果 |
| 时区 | 否 | 默认 `Asia/Shanghai` |
| 备注 | 否 | 不得包含不必要的敏感个人信息 |

首期接受标准 `.xlsx`。必须拒绝宏执行和公式执行。单文件默认上限 20MB、50,000 行，均为系统参数。旧 `.xls` 和 CSV 是否原生支持，在获得真实设备样本后再确认；首期可以通过字段映射将设备 `.xlsx` 归一化。

### 5.1 已交付模板实物审计

模板已核验为 6 个工作表、14 个主表字段、9 个设备人员映射字段和 4 行合成示例；无公式、宏或外部链接。当前模板的结构化表只覆盖一个空数据行，数据验证和预制样式只覆盖约 500 行，没有机器可读的模板版本定义名、发布日期或契约哈希。

这些限制不改变服务端 50,000 行契约：服务端不得依赖工作簿下拉或样式完成校验，必须逐行校验全部上传数据。后续模板波次应扩展可填写范围、加入机器可读版本/契约哈希，并在不放入真实数据的前提下完成可视化复验。

## 6. 员工与任职匹配

匹配优先级：

1. 员工工号唯一匹配，并验证打卡时点存在有效任职周期；
2. 未填工号时，按“场地编码 + 设备编号 + 设备人员编号”的有期限绑定匹配；
3. 姓名、部门仅用于核对，不能自动决定员工；
4. 同一编码匹配多人、员工不存在、越权组织、打卡落在离职空档期时均进入错误报告，不得猜测；
5. 二次入职按打卡时点匹配对应任职周期。

跨夜班归属哪个考勤日由班次和考勤引擎决定，导入阶段只保存原始时间、时区和来源。

## 7. 幂等、跨来源去重与多源重叠

### 7.1 文件级

使用租户、来源范围、文件哈希和模板/映射版本识别相同文件。换文件名再次上传同一内容不得重复写入，可允许重新预检并跳转原批次。

### 7.2 原始记录级

- 有原始记录 ID：使用“租户 + 来源系统/场地/设备 + 原始记录 ID”；
- 无原始记录 ID：使用“租户 + 场地 + 设备 + 设备人员/员工 + 标准化打卡时间 + 打卡方向”生成稳定指纹；
- 完全相同记录标记为重复并跳过，不新增原始打卡。

### 7.3 有效打卡级

- Excel 与得力 API 有相同设备流水号：认定为同一事实；
- 无相同流水号但同员工、同精确时间：认定跨来源重复；
- 同员工、同标准化方向、不同来源且时间差大于 0 秒并不超过 60 秒：默认创建一个 `PENDING_DUPLICATE_REVIEW` 候选组，保留全部 raw fact，但在人工裁决前生成 0 个 `ACTIVE` effective event，因而不进入考勤计算；
- 有权限人员确认“同一事实”后，候选组生成且仅生成 1 个 `ACTIVE` effective event；确认“不同事实”后，每条 raw fact 各生成 1 个 `ACTIVE` effective event；两种裁决都保存原因、操作者、版本和审计并触发受影响范围重算；
- 默认把近似重复作为非阻断警告：批次可以发布 raw fact 和待裁决候选组，但候选组在裁决前不向计算层提供 effective event；配置可把该警告升级为整批阻断。
- 60 秒窗口可配置，但配置变更只影响新预检/新计算版本，不静默改写已月结结果；
- 所有原始记录和来源标签继续保留；优先级只决定规范事件的主来源，不得删除证据；
- 正常的多次打卡不能在导入阶段被简单去重丢失。

默认来源优先级可配置为：`得力 API > 设备 Excel > 人工标准模板`。

## 8. 校验与错误

阻断或警告至少覆盖：

- 表头/字段映射缺失、类型或时间格式错误；
- 空白行、公式单元格、未来异常时间和时区缺失；
- 场地/设备未配置或不在操作者权限范围；
- 员工未匹配、姓名不一致、多人匹配、任职周期不匹配；
- 文件级重复、原始记录重复和跨来源疑似重复；
- 超过文件大小/行数限制；
- 涉及冻结或已月结期间；
- 部分有效、部分错误。

默认使用严格发布模式：存在阻断错误时整批不可发布。可提供“仅发布有效行”的受控配置；启用时必须明确确认、生成部分成功批次并保留错误行，不能静默忽略。

## 9. 月结保护、重算和作废

| 期间状态 | 默认行为 |
|---|---|
| 开放 | 发布后只重算受影响员工与考勤日期 |
| 预结算/冻结 | 允许上传和预检，禁止直接发布到计算结果 |
| 已月结 | 默认禁止发布和重算，必须先按权限重开期间 |
| 已重开 | 生成新计算版本、前后差异和审计，不覆盖旧版本 |

已发布批次不可物理删除。开放期间可按批次作废/冲正并重算受影响范围；冻结或已月结期间必须先重开。原始文件、文件哈希、原始行和操作审计始终保留。

## 10. 数据留痕

每批保存：批次号、来源类型、地点、设备、时区、原文件名、文件哈希、文件大小、模板/映射版本、总行数、各状态数量、上传人、发布人、时间、request_id。

每行保存：原始行号、原始值、标准化值、匹配员工/任职周期、幂等键、校验结果、错误码、规范事件 ID、计算版本和来源证据。

## 11. 验收标准

- AC01：有权限用户可下载版本化标准模板，模板含说明、主数据、设备人员映射、字段说明、枚举和合成示例。
- AC02：上传后必须先预检，未经二次确认不写入正式原始事实层。
- AC03：员工编码或设备绑定无法唯一匹配时不得自动猜测，错误报告包含原始行号和原因。
- AC04：同一文件换名重传、同一流水重复导入均不新增原始打卡。
- AC05：Excel 导入后相同记录再由得力 API 到达，只生成一个有效打卡，但全部原始来源可追溯。
- AC06：无原始记录 ID 时稳定指纹能够阻止完全重复，同时不删除正常多次打卡。
- AC07：开放期间只重算受影响员工与日期，不触发无关人员整月重算。
- AC08：冻结或已月结期间的上传、发布和重算不能静默改变已发布结果。
- AC09：重开期间后生成新的计算版本和差异，不覆盖旧结果。
- AC10：跨夜班打卡由班次引擎归属考勤日，不按自然日直接截断。
- AC11：批次作废后导入事件失效并完成受影响范围重算，原始证据和审计仍可查询。
- AC12：普通员工、无组织权限用户和系统管理员不能执行导入或读取越权原始文件。
- AC13：跨来源近似重复在默认 60 秒窗口内先进入 `PENDING_DUPLICATE_REVIEW`，裁决前无 active event；确认重复后恰有 1 个、确认不重复后恰有 2 个 active event，raw fact 始终不删除。
- AC14：预检失败、冻结阻断和发布事务失败分别落入 `VALIDATION_FAILED`、`BLOCKED_BY_FROZEN_PERIOD`、`PUBLISH_FAILED`，不得用一个模糊 `FAILED` 状态替代。
