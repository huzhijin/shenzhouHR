# 运维、技术选型与 ADR

## 1. 非功能目标

| 指标 | PRD V1.7 基线 | 验证方式 |
|---|---|---|
| 可用性 | 月度 99.5%，不含批准的计划维护 | 生产 SLI 按成功请求和可服务分钟计算 |
| 常用列表 | 50 并发下 P95 ≤ 2 秒 | 预发布脱敏规模数据压测 |
| 工作台/大屏 | P95 ≤ 3 秒 | 冷/热查询分别测试，标注数据更新时间 |
| 详情 | P95 ≤ 1 秒 | 含权限范围与字段策略开销 |
| 首个可用内容 | ≤ 2.5 秒 | 指定 PC/移动视口和企业网络基线 |
| 50,000 行导出 | ≤ 60 秒或进入异步任务 | 记录排队、生成、下载阶段耗时 |
| 同步 | 每 5 分钟；P95 可见 ≤ 10 分钟、P99 ≤ 30 分钟 | 外部接收时间至授权查询可见时间 |
| 月度计算 | 全月考勤/工资暂定 ≤ 30 分钟 | 以真实人数与月数据量 POC 校准 |
| 灾备 | RPO ≤ 15 分钟，RTO ≤ 4 小时 | 季度恢复演练实际时间与丢失点 |

## 2. 环境与发布边界

| 环境 | 数据 | 身份/密钥 | 外部连接 | 发布控制 |
|---|---|---|---|---|
| 开发 | 合成、不可反推个人 | 开发专用命名空间 | 默认模拟；真实沙箱需显式批准 | 开发者自助 |
| 测试 | 合成或不可逆脱敏 | 测试专用 | 合同测试/批准沙箱 | CI 质量门 |
| 预发布 | 生产等结构、脱敏规模 | 预发布专用 | 官方沙箱/只读测试源 | 变更审批、回滚演练 |
| 生产 | 真实业务数据 | root-only 环境文件或批准的密钥服务，最小权限 | 网络白名单，只读 OA、批准的得力端点 | 双人审批、审计、分批发布 |

构建产物一次生成、逐环境提升；配置与密钥不打包进产物。数据库迁移必须前向可执行、具备明确回滚/前滚策略；高风险 schema 采用 expand-migrate-contract，应用版本回滚不依赖破坏性降级。

## 3. 日志、指标、追踪与告警

### 3.1 结构化事件

统一字段：`timestamp`、`level`、`service`、`module`、`environment`、`correlation_id`、`trace_id`、`operation_id`、`job_id`、`actor_type`、`result_code`、`duration_ms`。仅用不可逆主体引用；禁止工资、个税、身份证明、原始坐标、附件内容、凭据、连接串、完整外部响应进入普通日志。

### 3.2 关键 SLI

- API：按 route template 的请求量、错误率、P50/P95/P99、拒绝率；不把 employee ID 放标签。
- 同步：外部到本地延迟、水位年龄、页数、重复率、隔离记录数、重试次数、429/109/110。
- 考勤：待计算量、计算耗时、阻断/异常率、重算差异。
- 工资：仅记录运行数量、状态和耗时；金额不进入指标标签或日志。
- 安全：认证失败、拒绝决策、异常导出、权限变更、break-glass、审计链验证失败。
- 数据库：连接池、慢查询摘要、复制延迟、binlog 归档、备份年龄、存储增长。

### 3.3 告警分级

| 级别 | 条件示例 | 响应 |
|---|---|---|
| P1 | 审计链验证失败、疑似工资越权、主库不可用、备份连续失败 | 立即通知安全/值班；冻结相关导出或发布，启动事件响应 |
| P2 | 同步 P99 超 30 分钟、任务失败率突增、复制延迟逼近 RPO | 15 分钟内确认，执行重试/切换/限流预案 |
| P3 | 单批隔离记录、容量预测阈值、非核心延迟退化 | 工作时间内处理并关联工单 |

告警只携带关联 ID 和处置链接，不含工资或个人敏感明细。每条告警有负责人、抑制窗口、升级链、运行手册和解除条件。

## 4. 备份、恢复、RPO 与 RTO

- MySQL 每日全量备份 + 连续 binlog 归档实现 PITR，备份加密并复制到独立故障域；文件存储启用版本化、保留锁和生命周期。
- 备份服务账号只能写备份，恢复账号按需启用；密钥与数据备份分离。每日自动验证清单和校验和，但“备份成功”必须由恢复证明成立。
- 季度执行隔离环境全量恢复：恢复数据库、对象引用、审计链与配置版本；记录恢复点差值 ≤15 分钟、业务可服务时间 ≤4 小时。
- 年度执行主区不可用演练；月结/工资发布窗口前执行恢复就绪检查。恢复后对工资总额控制数、员工/组织版本数、月结摘要和审计链锚点做一致性比对。
- 破坏/勒索场景采用不可变备份和独立权限；恢复操作本身写安全审计，不覆盖事故现场证据。

## 5. 容量与韧性

在线查询、同步任务和导出任务使用独立线程池与数据库连接配额，防止 Excel/导出或外部重试耗尽在线资源。任务租约、幂等键、调度状态和 Outbox 均落 MySQL；首版不依赖 Redis 或消息队列。所有外部调用有连接/读取总超时、并发上限和熔断；熔断只暂停新同步，不影响本地读。工资发布和月结关闭不能在数据库只读/复制异常、审计链不可用或输入水位过期时继续。

## 6. 已确认技术栈

`docs_confirm` 已于 2026-07-20 人工通过，技术栈不再保留双方案：

| 层级 | 决策 | 边界 |
|---|---|---|
| 操作系统 | Ubuntu Server 24.04 LTS | 原生安装，按官方安全更新节奏维护 |
| 前端 | React 19 + TypeScript + Vite + Ant Design | SPA；PC、移动自适应与独立大屏路由；图标统一使用 Tabler Icons |
| 后端 | Ubuntu 官方 OpenJDK 21 + Spring Boot 4.1.0 + Maven | 模块化单体；补丁版本由依赖锁定并通过兼容测试；[Spring Boot 官方系统要求](https://docs.spring.io/spring-boot/system-requirements.html) |
| 数据访问 | MyBatis + MariaDB Connector/J | 外部精确 ID 使用字符串；金额使用 `DECIMAL`；禁止 ORM 隐式跨模块查询 |
| 数据库 | MySQL 8.4 LTS Community，InnoDB、`utf8mb4` | binlog + PITR；表名和迁移脚本显式管理；[MySQL LTS 发布模型](https://dev.mysql.com/doc/refman/8.4/en/mysql-releases.html) |
| 网关与进程 | Nginx + systemd | Nginx 托管前端并代理 `/api`；后端只监听回环地址 |
| 契约与可观测 | OpenAPI 3.1 + OpenTelemetry | 契约生成类型；日志禁止敏感数据 |
| 首版排除 | Docker、Kubernetes、Redis、消息队列、微服务 | 任务锁、幂等、调度、Outbox 先由 MySQL 承担 |

许可证基线：只允许经批准的商业友好或已完成法律评估的依赖；Maven/NPM 锁定版本并生成 SBOM、许可证清单与 `THIRD-PARTY-NOTICES`。开发默认使用 Ubuntu 官方 OpenJDK、Maven、Node.js、VS Code 或已购正版 IDE；不得把“可下载”等同于“可用于当前企业场景”。

## 7. 技术选型评分与验证门

| 指标 | 权重 | 机械证据 |
|---|---:|---|
| 团队可维护性 | 25% | 2 名目标维护者在 2 天内完成同一变更并通过测试 |
| 安全与权限表达 | 20% | 对象/字段/范围负向测试全绿，响应字段白名单可审计 |
| 集成适配 | 20% | 致远脱敏样本、得力官方契约样本全通过，19 位 ID 不变 |
| 规则与批处理 | 15% | 代表规模下月计算达到 PRD 暂定目标，无内存峰值失控 |
| 可观测与恢复 | 10% | trace 贯通、任务重跑、迁移/备份恢复演练通过 |
| 总成本 | 10% | 三年许可证、基础设施、人员和升级成本清单 |

任何方案存在一项安全/数据精度硬失败即淘汰，不以加权分掩盖。

## 8. ADR 架构决策记录

### ADR-001：首期模块化单体

- 状态：已接受。
- 决策：单部署单元、模块独立 schema/仓储接口、事件解耦，按可量化触发条件拆分。
- 理由：当前无团队规模、容量或独立部署证据支持微服务。
- 代价：需要严格模块边界测试和代码所有权，部署仍是整体。
- 否决方案：首期大量微服务；增加分布式事务、权限上下文和运维复杂度。
- 验证：模块依赖静态检查；禁止跨模块表访问；故障/容量指标达到拆分阈值再复审。

### ADR-002：P0 包含完整工资模块但不含付款

- 状态：已由当前需求确认。
- 决策：包含采集、项目/方案、分段、社保公积金个税、复核发布、工资条；排除银行账号和付款文件。
- 理由：当前提示比 PRD 早期范围痕迹更新、更明确。
- 代价：P0 安全、测试和合规工作显著增加。
- 否决方案：只做考勤或工资演示；不符合目标。
- 验证：AC-PAY 和 AC-PSEC 全量映射并测试。

### ADR-003：内部员工身份与来源绑定分离

- 状态：已确认。
- 决策：不可变 `employee_id`；OA CODE 只用于创建/核验时态绑定。
- 理由：工号变化、重复和跨系统历史需要稳定引用。
- 代价：需要冲突工作台和历史绑定查询。
- 否决方案：运行时按工号 join；会误归属并改写历史解释。
- 验证：工号变更前后考勤、工资、权限仍引用原快照。

### ADR-004：组织身份/版本/任职/投影四层分离

- 状态：已确认。
- 决策：自动同步当前投影，管理员动作产生正式组织版本。
- 理由：满足历史报表、拆并、ID 复用和调动日归属。
- 代价：时态查询和版本比较复杂。
- 否决方案：覆盖式组织表；无法追溯。
- 验证：跨变更日查询返回各自版本，历史合计不漂移。

### ADR-005：自建表以版本化映射解耦

- 状态：已确认。
- 决策：`SeeyonCustomTableReader + OAQueryMappingProfile`，物理字段本轮不定。
- 理由：不阻塞总体架构且避免外部模式污染领域。
- 代价：增加映射发布、验证和回滚能力。
- 否决方案：在领域/SQL 中写死物理字段。
- 验证：切换 mapping profile 不修改领域代码，旧记录保留旧版本引用。

### ADR-006：未知坐标不转换、不绘点

- 状态：已确认。
- 决策：原始坐标、坐标系、校验和转换状态分离；`UNKNOWN` 时仅展示状态。
- 理由：得力官方资料未明确坐标系，静默转换会产生虚假证据。
- 代价：确认前地图覆盖率降低。
- 否决方案：默认 WGS84/GCJ02；不可验证。
- 验证：未知/非法/缺失样本的 `map_point_available=false`。

### ADR-007：默认拒绝的独立 PAYROLL 权限域

- 状态：已确认。
- 决策：工资权限、字段策略、导出、审计和职责分离独立；系统管理员无隐含读取权。
- 理由：工资是最高敏感数据且存在内部威胁。
- 代价：管理与测试矩阵增大。
- 否决方案：通用管理员全权或前端隐藏。
- 验证：普通员工、主管、系统管理员全部负向测试，响应不含原始金额字段。

### ADR-008：技术栈在人工作出选择后冻结

- 状态：已接受，2026-07-20 人工确认。
- 决策：采用 `React 19 + TypeScript + Vite + Ant Design`、`OpenJDK 21 + Spring Boot 4.1.0 + Maven + MyBatis`、`MySQL 8.4 LTS Community`，运行于 Ubuntu Server 24.04 LTS，由 Nginx + systemd 原生部署。
- 理由：满足国内企业集成、快速上线、长期维护和正版合规目标，并减少首版运行组件数量。
- 代价：首版任务调度、租约与 Outbox 会增加 MySQL 压力，需要以代表规模验证；单机部署在高可用要求提升后需要扩展。
- 否决方案：.NET 双方案、Oracle JDK、Vue、PostgreSQL，以及首版引入 Docker/Kubernetes/Redis/消息队列。
- 验证：19 位 ID、权限负测、MySQL 幂等/租约、迁移回滚、依赖许可证与 SBOM 全部通过。

### ADR-009：运行时模型提供商保持可替换

- 状态：边界决策；当前 PRD 未定义 AI 业务功能，首期不新增 AI 页面或决策链。
- 决策：若后续经需求变更引入运行时 LLM，只能通过薄的 OpenAI-compatible provider 端口接入；模型 ID、base URL、API-key 环境变量名均由配置提供，不硬编码 Anthropic/Claude 或 `ANTHROPIC_API_KEY`。
- 理由：模型选择与开发工具所用模型无关，且不应污染 HR 领域模块。
- 代价：增加适配与合规评估；未获明确用例前不实现。
- 否决方案：把任一供应商 SDK 分散写入业务代码。
- 验证：更换 Qwen/DeepSeek/Zhipu/Moonshot/OpenAI/Ollama 兼容端点无需改业务代码；密钥只存在密钥服务。
