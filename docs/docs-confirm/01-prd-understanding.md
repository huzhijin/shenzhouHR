# PRD V1.7 理解与差异说明

> 来源：`docs/神州HR考勤与薪资核算系统_PRD_V1.7.docx`（V1.7，2026-07-19，集成校准版）。本摘要不替代原始 PRD。

## 1. 产品边界

系统是面向企业内部的考勤与薪资核算平台，以致远 OA 为组织、人事和自建业务单据来源，以得力 E+ 为原始打卡来源，以 HR Excel/系统维护为工资输入。首期采用边界清晰的模块化单体，服务 PC、独立移动信息架构和 1920×1080 数据大屏。

P0 覆盖组织版本、人员绑定、同步任务、考勤原始/标准化/计算/调整/月结分层、假勤关联、位置证据、报表、年假、薪资采集与项目方案、分段核算、社保公积金个税、工资发布与工资条、权限与审计、运维配置。历史考勤不迁移；银行付款文件和银行账号流程明确排除；工资不增加审批流。

## 2. 不可破坏的领域不变量

1. `employee_id` 是不可变内部主键；致远 OA `CODE` 是权威工号，只用于建绑定。绑定后业务归属必须引用 `employee_id` 和当时版本，不得运行时临时跨系统匹配。
2. 致远 19 位或更长 ID 在 API、消息、数据库边界和前端一律表示为字符串或精确十进制，禁止 JavaScript `Number`。
3. 组织身份、组织版本、来源绑定、任职历史和当前投影分离；变更只追加版本，不能覆盖历史。调动生效日 00:00 起归属新组织。
4. 致远自建表是只读来源，经版本化 `OAQueryMappingProfile` 映射到逻辑契约；不得将物理表名/字段写入领域模型，不得向 OA 执行任何写操作。
5. 得力同步必须保留原始载荷摘要、同步批次、精确游标和来源记录 ID；重复、重试和人工重跑不产生第二条业务打卡。
6. 考勤按“原始数据 → 标准化 → 规则证据 → 计算结果 → 人工调整 → 月结快照”分层。月结后冻结；重开、重算和补偿均追加差异与审计。
7. 工资运行只读取冻结输入快照和规则版本；同一员工同一工资期间可以有多个半开区间 `PayrollSegment`。已发布工资不可改写，补发、补扣、冲销生成新记录。
8. `PAYROLL` 是独立、默认拒绝的权限域；系统管理员、部门负责人和普通员工不会因技术权限或前端修改得到工资明细。

## 3. PRD 中必须原样落实的规则

| 主题 | 已确认基线 | 尚待参数化但不阻塞总体架构 |
|---|---|---|
| 总部作息 | 夏季 05-01 至 09-30：08:30–18:00；冬季 A 01-01 至 04-30：08:30–17:30；冬季 B 10-01 至 12-30：08:30–17:30 | 12-31 与午休区间 |
| 地区/个人优先级 | 个人规则 > 地区规则 > 总部季节规则 | 具体适用名单由可版本配置提供 |
| 大连 | 07:30–12:00、13:00–16:30 | 晚餐扣除不是全局固定规则，按方案配置 |
| 成都 | 指定人员 09:00–12:00、13:00–18:00 | 指定人员范围待业务名单 |
| 年假 | 满一年后 5 天/年，最小 0.5 天；半天按实际半日班段，不固定折算 4 小时 | 跨年、折算和结转策略 |
| 假期最小单位 | 病假 0.5 天；事假 0.5 小时 | 丧假 3/1 天的工作日或自然日口径；护理假适用和连续性 |
| 补卡 | 一周内；设计默认 7 个自然日并版本化 | 起算点、截止时刻与例外授权 |
| 加班 | 首次申请在 48 个自然小时内，审批通过且有重叠打卡证据；超过 48 小时最终计 0 | 时区统一采用企业业务时区 |
| 提前返岗 | 支持 `AUTO_FULL_PUNCH`、`OA_CANCEL_ONLY`、`HR_CONFIRM`、`HYBRID` | 各假种默认策略 |

## 4. 输入—处理—输出—异常总览

| 核心能力 | 输入 | 处理 | 输出 | 失败关闭行为 |
|---|---|---|---|---|
| 组织人员 | 致远标准组织/人员、手工正式同步动作 | 指纹比较、版本追加、绑定冲突检测 | 当前投影、组织版本、任职历史 | 缺失/重复 CODE 不自动归属，进入人工核验 |
| OA 单据 | 自建表只读结果、映射配置版本 | 逻辑字段映射、校验、去重、标准化 | 假勤/调动等标准业务事实 | 映射缺失隔离该记录，保留原始摘要，不猜字段 |
| 得力打卡 | 游标分页 API 数据 | 验签、限流、精确游标、幂等去重、位置校验 | 原始打卡与标准化打卡 | 超时重试；游标不越过失败页；坐标不明不画点 |
| 日考勤 | 班次/规则版本、任职、打卡、OA 事实 | 按证据顺序计算并生成原因码 | 日结果、异常、可追溯证据链 | 关键输入缺失标记阻断/待复算，不静默给正常 |
| 月结 | 日结果、水位、规则版本、未决异常 | 预检、计算、复核、冻结 | 月结快照、差异、重开记录 | 存在阻断项不得关闭 |
| 工资 | 冻结主数据、考勤月结、工资输入、税费规则 | 输入锁定、按有效期切段、公式计算、复核、发布 | 工资结果、分段成本、工资条 | 失败不发布；已发布记录不可覆盖 |
| 授权 | 身份、角色、组织/对象/字段/时间/操作/导出范围 | 服务端策略求交、目的校验、字段白名单 | 允许的最小字段集或统一拒绝 | 策略/范围/依赖不可用即拒绝 |

## 5. 当前提示与 PRD 的差异裁决

| 冲突/补充 | 裁决 | 记录 |
|---|---|---|
| PRD 内仍有工资范围不完全确定的早期痕迹 | 采用当前明确要求：P0 必须包含完整工资核算，且含社保、公积金、个税 | ADR-002 |
| PRD 对工号匹配表达较宽 | 采用当前明确要求：OA CODE 权威、得力工号一致；匹配后固化 `EmployeeSourceBinding`，冲突人工核验 | ADR-003 |
| PRD 对组织同步偏当前投影 | 采用当前明确要求：自动同步当前投影，管理员动作形成正式组织版本；历史不可覆盖 | ADR-004 |
| PRD 可能将自建表物理字段列为开放输入 | 当前阶段明确忽略物理名；用 `OAQueryMappingProfile` 解耦，不作为总体架构阻断 | ADR-005 |
| 得力官方未声明坐标系 | 不能推测或静默转换；保存原始值与验证状态，未确认不展示准确点 | ADR-006 |

## 6. 准入分级

- **总体架构可以继续**：领域边界、主数据历史化、同步可靠性、权限模型、考勤和工资状态机均有足够输入。
- **接口详细设计待联调**：致远自建表映射实例、致远标准 API 版本与权限、得力租户返回样本/限流窗口、坐标系、附件下载授权、Excel 模板列级规则。
- **生产上线前必须关闭**：真实凭据与密钥托管、网络白名单、数据分类加密实现、备份恢复演练、渗透测试、高危问题清零、正式 Logo 授权文件、RPO/RTO 负责人签字。

## 7. 架构准入结论

沿用并收紧 PRD V1.7 结论：**有条件通过**。条件是本轮文档经 `docs_confirm` 人工确认；随后先冻结技术栈、OpenAPI 与规则参数，再进入前端。缺少自建表物理字段不阻塞总体架构，但阻塞相应映射实例的联调完成声明。
