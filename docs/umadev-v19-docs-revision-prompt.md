# V1.9 docs_confirm 修订提示词

当前 `docs_confirm` 暂不批准。请保持在当前 gate，只修订文档、规格、契约方案和设计交接，不修改前后端业务源码或数据库迁移。

请逐条复核 PRD V1.9、`docs/umadev-v19-master-prompt.md` 和人工评审意见，输出“问题—原内容—修订内容—受影响验收”的差异表，并至少确保：

1. 登录为本系统独立账号密码，不再保留“SSO 待定”作为当前方案；
2. 组织仅做期初 Excel 导入，发布后由本系统独立维护；不得设计定时、手动持续或双向组织同步；
3. OA 考勤业务单据只读接入与“取消组织同步”的边界清楚；
4. 特殊城市、人员及夏冬令时通过考勤组、班次版本、生效期和适用范围实现；
5. 所有考勤组默认扣除晚餐，工作日、周末和节假日的窗口、时长与触发条件可配置；
6. 每人每自然月默认有 1 次大于 0 且不超过 15 分钟的迟到宽限，规则可配置；
7. 单边缺卡定义为某个工作段仅有一侧打卡，默认补正期限 7 个自然日，逾期默认仅影响该工作段；
8. 所有假别采用版本化配置，默认按工作日计算；
9. 年假资格与档位分离：最新任职周期本公司满一年是默认可配置资格门槛，累计工龄决定 5/10/15 天档位；
10. 年假默认周年日发放、下一周年日前一天到期，二次入职从最新入职日重新计算；
11. 支持员工期初工时、调休、年假余额 Excel 导入及余额流水；
12. 无网络地点、非得力和异构考勤机的原始打卡支持 Excel 导入；必须有版本化真实模板、厂商字段映射、设备人员/员工匹配、预检、文件与记录幂等、API/Excel 跨来源去重、错误报告、影响预览、批次发布、作废/冲正、月结保护和原始行审计；不得把它设计成批量补签或直接导入迟到/旷工结果；
13. 薪资前端默认完全不可发现，服务端为独立 `PAYROLL` 默认拒绝权限域；
14. 所有规则采用受控字段、版本、生效期、作用范围、冲突检测、试算、发布、审计和回滚，不能使用任意脚本或散落硬编码；
15. 旧 V1.7 文档和 Open Design 提示词只保留为清楚标记的历史资料。

修订后的验收标准必须可直接转成测试。不得虚构未读取的 Open Design 产物；缺失项标为 `MISSING`。完成后继续停在 `docs_confirm`，等待人工批准。
