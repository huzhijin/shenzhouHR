# 神州 HR · Open Design V1.9 批量生成到大屏前

> 当前适用状态：`V19-OD-00` 是唯一活动基线，`V19-OD-01` 已完成。将下面第一个代码块一次性粘贴到当前同一个 Open Design 项目，不要点击“智能匹配下一步”。

```text
Use open-design.

【本轮批量执行指令｜覆盖此前“每轮只生成一个 artifact”的限制】

继续当前同一个“神州 HR V1.9”项目，不创建新项目。以 `V19-OD-00` 为唯一 `ACTIVE_BASELINE`，保留并读取已完成的 `V19-OD-01`、最新 artifact-index 和 design-handoff。

本条消息仅在本轮临时覆盖此前“每轮只生成一个 artifact、完成一个就停止”的执行方式。请在同一次运行中，按照依赖顺序连续生成大屏之前所有尚未完成的 artifact：从 `V19-OD-02` 开始，完成至 `V19-OD-14` 后统一停止。不要在每个 artifact 之间回复、暂停、请求确认或等待用户再次点击。

一、必须按顺序处理的队列

1. `V19-OD-02 角色工作台与三级看板`
2. `V19-OD-03 组织与员工期初导入`
3. `V19-OD-04 本地组织、员工与任职周期`
4. `V19-OD-05 统一规则配置中心`
5. `V19-OD-06 考勤组、班次与工作日历`
6. `V19-OD-07 晚餐、迟到宽限与缺卡策略`
7. `V19-OD-08 假别与周年年假策略`
8. `V19-OD-09 时间账户与期初余额导入`
9. `V19-OD-10A 离线考勤打卡 Excel 导入`
10. `V19-OD-10B 在线考勤机与 OA 考勤业务单据接入`
11. `V19-OD-11 考勤工作台、日明细与证据链`
12. `V19-OD-12 异常、重算、月结与报表`
13. `V19-OD-13 员工自助与移动端`
14. `V19-OD-14 权限、账号、审计与系统运维`

先读取 artifact-index：已经完整完成并通过自检的队列项可以跳过，但必须核验它仍符合唯一活动基线；草稿、失败、不完整或只生成说明文字的项目不算完成，应继续补齐。不得重复生成 `V19-OD-01`。

二、批量执行不等于合并页面

- 上述每一项仍必须生成独立、可单独打开和评审的 artifact，并保持稳定命名；严禁把 `V19-OD-02` 至 `V19-OD-14` 合并成一个巨型仪表盘、长页面、文档或单一原型。
- 每完成一个 artifact，立即在内部更新 artifact-index、design-handoff 和 QA 状态，再自动进入下一项；中间不要向用户回报。
- 复用同一套 `shenzhou-hr` 组件、tokens、AppShell、响应式规则和语义化 `data-od-id`，但不能用重复占位页面代替真实业务交互。
- 每个 artifact 都必须完成一次 critique/refine，至少修正一个层级、密度、对齐、溢出、响应式、无障碍或错误状态问题，并记录结果。

三、每个 artifact 的共同交付要求

- 覆盖 PC、平板、手机的适用布局；复杂桌面表格在手机端改成卡片、分组列表或渐进披露，不允许直接缩小。
- 覆盖正常、加载、空数据、失败、无权限、冲突、冻结、处理中、部分成功和成功等与该模块适用的状态。
- 高风险操作必须有影响范围、人数/记录数、期间、可逆性和确认层；上传、预检、发布、作废/冲正、重算、月结、反月结和导出按不同权限表达。
- 所有结果型页面提供可解释的“为什么”：输入事实、规则版本、计算过程、结果与下一步。
- 使用合成数据，不展示真实姓名、工资、精确位置或敏感假别原因。
- 薪资只允许后端预留，前端必须完全不可发现；导航、路由、工作台、搜索、报表、员工端、移动端和空状态均不得出现薪资、工资条或“暂未开放”入口。
- 不修改 `LEGACY-V17`、`V19-OD-00` 或 `V19-OD-01`；不改写 `ACTIVE_BASELINE`；旧薪资 artifact 继续为 `FUTURE_RESERVED`。
- 不解析 DOCX、不上传 PRD、不执行 PRECHECK，不因本地文件不可读或 Design System 未激活而停止。设计规范按 `ACTIVE → PROJECT_EMBEDDED → INLINE_FALLBACK` 自动选择并继续，如实记录实际模式。

四、跨 artifact 关联与客户演示联动

本批次必须形成一个可以从 `V19-OD-01` 登录后连续点击演示的统一原型，而不是互不相连的页面图片。跨 artifact 交互使用稳定的 artifact/route/data-od-id 目标，并满足：

- 全局导航、面包屑、返回、标签页、列表行、详情链接、待办卡片、指标卡、按钮、抽屉、弹窗和导入向导的关键入口都可点击；不得把主链路按钮做成无响应装饰。
- 登录后根据所选演示角色进入对应 `V19-OD-02` 工作台；角色切换应同步改变导航、数据范围和可执行动作，并能演示 403/无权限，但不得短暂显示上一角色数据。
- 工作台待办、异常数、待发布批次、月结进度和数据新鲜度卡片应带预设筛选跳转到对应业务页面；目标页面提供明确返回路径，返回后保留原筛选和上下文。
- 跨页面使用同一套合成数据主键和状态，不能在不同 artifact 中让同一员工、部门、期间、规则版本或导入批次出现相互矛盾的数字。
- 允许使用客户端原型状态模拟“保存草稿、预检、发布、解决异常、重算、月结”等演示效果；操作后关联页面的状态、数量、时间线和待办应同步变化，并提供“重置演示数据”。必须在 handoff 标记为 `PROTOTYPE_SIMULATION`，不能声称真实后端、接口或持久化已完成。
- 保留一个仅供原型演示使用、不会进入正式产品导航的“演示场景/重置”悬浮入口或演示控制条；明确标记 `PROTOTYPE_ONLY`，交付 UmaDev 时默认不实施到生产前台。
- 每生成一个新 artifact，都要回接此前已完成 artifact 的相关入口，并修复新增的断链；批次结束前执行一次全链路 dead-link 检查。
- 开始批处理前建立并持续维护共享 `route-to-artifact` 注册表和 `demo-data-registry`；所有 artifact 只能引用注册表中的稳定路由与合成数据主键。
- `V19-OD-01` 不得重新设计或修改视觉，只允许补充“登录成功 → V19-OD-02 对应角色工作台”的原型跳转关系。
- 尚未模拟的非主链路动作必须明确标为“原型未接入/待工程实现”，不得伪装成可用功能；但下列五条客户演示主链路不能以此为由留死链。

统一使用以下合成演示锚点，也可补充但不得改名或改变含义：

- 演示月份：`2026-07`
- 部门：`制造一部`、`研发一部`、`人力资源部`
- 员工：`EMP-DEMO-001 演示员工甲`、`EMP-DEMO-002 演示员工乙`
- 无网地点：`离线厂区 A`
- 组织期初批次：`ORG-INIT-DEMO-001`
- 时间账户期初批次：`TIME-INIT-DEMO-001`
- 离线打卡批次：`ATT-XLS-DEMO-001`
- 在线打卡来源：`DEVICE-DEMO-01`
- 考勤策略版本：`ATT-POLICY-DEMO-V3`

至少打通并自检以下五条客户演示主链路：

1. `本地登录 → HR 工作台 → 组织/员工期初导入 → 导入发布 → 本地组织树 → 员工任职周期 → 入职前累计工龄 → 周年年假资格与档位试算`。
2. `考勤管理员工作台 → 离线考勤 Excel 模板/上传 → 字段映射 → 人员匹配 → 预检与 API/Excel 重复 → 发布 → 批次详情/原始行 → 考勤日明细证据链`。
3. `统一规则中心 → 考勤组/夏冬令班次 → 晚餐扣除 → 每月 1 次且 15 分钟内迟到宽限 → 单边缺卡 7 日补正 → 样例员工试算 → 影响预览 → 发布`。
4. `异常待办 → 缺卡证据/补正 → 人工调整 → 重算差异 → 月结阻断 → 处理未发布离线批次 → 月结完成 → 部门报表`。
5. `员工移动端 → 我的今日/月历 → 迟到宽限或缺卡“为什么” → 假期余额 → 周年年假发放与到期解释 → 反馈进度`。

在 design-handoff 中维护 `demo-flow`：每条链路的起点、点击步骤、目标 artifact、演示角色、前置状态、预期状态变化、重置方法和仍未实现的跳转。批次完成时不能存在未说明的主链路断点。

在 `route-to-artifact` 中记录每个页面的 artifact、路由、入口角色、来源页、返回页和关键上下文参数；在 `demo-data-registry` 中记录共享部门、员工、期间、任职周期、累计工龄、规则版本、导入批次、原始打卡、异常、余额和月结状态。跨页跳转必须保留当前演示角色、月份、部门、员工、批次及筛选上下文。

五、关键业务边界必须保持

- 独立账号密码登录；致远组织仅做期初 Excel 导入，之后本系统独立维护，没有持续组织同步；OA 考勤业务单据仍是只读来源。
- 夏令/冬令和特殊作息通过考勤组、班次版本、生效期和作用范围配置；所有考勤组默认扣除晚餐且规则可配置。
- 每名员工每自然月默认 1 次、15 分钟内迟到宽限；单边缺卡默认 7 个自然日补正，逾期默认仅影响缺卡工作段；均可配置。
- 假别默认按工作日且全部配置化。年假资格是最新任职周期本公司连续满 12 个完整日历月，档位依据累计工龄；周年发放、下一周年日前一天到期，二次入职从最新入职日重新计算。
- 组织/员工期初导入、时间账户期初余额导入、离线/异构考勤机原始打卡导入是三个独立入口和流程。
- 离线打卡导入必须包含标准模板、厂商字段映射、设备人员匹配、预检、错误报告、API/Excel 跨来源去重、冻结期间保护、发布、批次及原始行追溯；它不是补签入口，也不允许导入迟到、早退、旷工等计算结果。
- 新规则不得静默改写冻结或已月结期间；规则采用版本、生效期、作用范围、优先级、冲突检测、样例试算、发布、审计和回滚。

六、硬停止边界

完成并自检 `V19-OD-14` 后立即停止。绝对不要生成、预生成、改写或占位：

- `V19-OD-15 独立考勤数据大屏`
- `V19-OD-16 全项目 QA 与设计交接`

不要自动切换任务类型。`V19-OD-15` 需要用户之后手动切换为“自由形式 Live artifact”再单独生成。
在 artifact-index 中保持 `V19-OD-15 = NOT_STARTED / WAITING_FOR_MANUAL_SWITCH_TO_FREEFORM_LIVE_ARTIFACT`，不得生成它的页面、画板、文件、路由、缩略图、占位稿或内容草案。

七、异常与平台限制处理

- 本提示词已有答案的内容不得追问；普通歧义采用通用 HR SaaS 的安全默认值，记录到 assumptions 后继续。
- 单个 artifact 失败时先在同一运行中自我修正并重试；仍无法完成时标记 `MISSING/BLOCKED`，不得伪报完成，并继续生成依赖关系允许的后续项，最终统一报告。
- 如果平台存在无法绕过的硬性运行/产物上限，只允许在当前 artifact 完整保存、索引更新后停止；明确报告“最后完整完成项、未完成项、下一项”，不得把未生成项标记为完成。除此之外不得主动拆批。
- 不要先回复执行计划，不要逐项输出聊天总结，直接开始生成独立 artifacts。

全部完成后只输出一次批次总结：

1. 实际新生成、跳过和修复的 artifact 清单；
2. 每项 QA/critique 状态；
3. 唯一 `ACTIVE_BASELINE`；
4. 五条客户演示主链路的可点击状态、入口和 `PROTOTYPE_SIMULATION` 说明；
5. dead-link 检查结果；
6. `route-to-artifact` 和 `demo-data-registry` 一致性结果，以及仍属于 `ENGINEERING_ASSUMPTION / NOT_VERIFIED` 的后端能力；
7. 当前下一项明确为 `V19-OD-15`，但尚未生成；
8. 若无 MISSING/BLOCKED，输出 `BATCH_COMPLETE_THROUGH_V19-OD-14`；否则输出 `BATCH_PARTIAL_THROUGH_V19-OD-14` 并列出准确断点；
9. 提示用户：“大屏前的 Web Prototype 与关联演示链路已处理完成。请先按 demo-flow 验收，再手动切换为自由形式 Live artifact，发送大屏专用提示词。”
```
