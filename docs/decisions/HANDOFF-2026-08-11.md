## 8. 报表数据权限缺陷（客户 2026-08-11 明确提出）

### 客户要求

> 报表的权限管理这块是由管理员进行分配的，角色是可以多选的，不能让普通账号也有权限进行选择，
> 数据权限这块必须要控制好。

### 服务端是对的

`GET /api/v1/attendance-reports/scopes` 实测返回 4 条，**全部是「公司 HR」**，只是公司不同
（江苏神州 / 深圳神州 / 上海晟州聚能 / 深圳芯逸）—— 因为该账号确实在 4 家公司持有 HR_ADMIN。
下拉本该是「切换我有权限的哪家公司」，不是「切换我是什么角色」。端点有
`ATTENDANCE_REPORT:READ` 权限守卫。

`AttendanceReportQuery` 的注释声明：

> The caller never supplies a data scope. The server resolves every scope from the
> authenticated principal's role assignments, so a tampered request cannot widen visibility.

篡改测试：伪造 `scopeReference` 为 `SELF`、`ORG:fake-org-id`、别家公司 ID、`bogus-reference`，
四次均返回同一个 409，服务端**没有采纳**传入值。

> **⚠️ 该测试不充分**：投影表为空，请求没走到取数那一步。**有真实数据后必须重测一次**。

### 缺陷在前端

客户截图显示的是 `公司HR / 高管 / 部门负责人 / 本人` **四个角色级别**，
与 `frontend/src/features/reports/customerReportAccess.ts` 里硬编码的四个预设完全一致。
该文件自己的注释写着：

> falls back to these presets only when that lookup fails

截图左上角「数据尚未加载」正是查询失败（409）触发了回退。
所以那个下拉渲染的是**前端硬编码兜底清单，不是服务端返回值**。

相关位置：
- `frontend/src/features/reports/CustomerReportCenterPage.tsx:445-457`（Select，options 来自 `resolvedScopes`）
- `frontend/src/features/reports/customerReportAccess.ts:33/41/49/57`（四个硬编码 actorLabel）

### 修复方案（未做）

1. **删掉前端兜底清单**。scope 只能来自服务端；查询失败时下拉置灰并提示「权限加载失败」，
   绝不显示预设角色
2. **只有一个授权时隐藏下拉**（普通员工只有「本人」，不该出现选择器）
3. **角色由管理员分配、支持多选** —— `AccountsPage.tsx` / `AccountDetailPage.tsx` 已有角色分配
   和「高管默认全部启用公司」的提示雏形，但**是否真支持多选未核实**，需单独查
4. 有真实数据后**重做篡改测试**，确认服务端在有数据时也不采纳客户端传入的 scope

## 11. 环境陷阱（已踩过，别重复）

1. **出网能力会变**。本轮早期 curl 得力/GitHub/8.8.8.8 全部超时（exit 28），后期
   `v2-api.delicloud.com` 返回 200、`doc.delicloud.com` 返回 302。**每次要用网络前重新探测**，
   不要沿用旧结论
2. **`nc -z` 会假阳性** —— 对同主机确定关闭的端口也返回 OPEN。判断连通性**只能用 curl**
3. **工具环境会成段失联** —— `echo ok`、`printf`、`true`、Read 已知存在的文件全部返回空。
   本轮的 9 次误报全部发生在这些时段。**连续 2 次空返回就停下来说明**，不要凭记忆编造
4. Read 工具偶发返回重复行/乱码。用 `python3` 逐行打印可拿到准确内容；
   **编译和测试结果才是最可靠的仲裁**
5. zsh 里 `--include` 通配符要加引号（`--include='*.java'`），否则报 `no matches found`
6. 命令别存进变量再执行，会被当成单一路径
7. 猜表名/列名浪费了很多轮。已核实：员工工号列是 **`employee_code`**（非 `employee_number`）；
   账号表是 **`local_account`**（非 `account`）；`auth_principal` **没有** `username` 列
8. Flyway wrapper 必须同时给 `-configFiles=` 和命令，否则报 `unsupported Flyway argument`
