## 3. V1.9 已确认业务基线

### 3.1 登录、组织和人员

1. 系统使用独立账号密码登录，不依赖 OA SSO。需设计账号生命周期、密码安全存储、首次改密、失败锁定、重置、会话失效、退出、权限和审计。
2. 致远 OA 组织架构仅在期初通过 Excel 导入。导入发布后，以本系统组织架构为准并由本系统独立维护。
3. 本期不建设组织架构的定时同步、手动持续同步、双向同步或 OA 组织变更任务。该取消只针对“组织架构同步”，不代表取消已确认的 OA 请假、加班、外出、出差、补卡等考勤业务单据的只读接入。
4. 组织与员工导入必须支持模板下载、字段说明、上传、预校验、差异预览、错误报告、幂等键、批次发布、撤销边界和完整审计。
5. 二次入职必须创建新的任职周期并保留历史，不得覆盖第一次任职记录。
6. 特殊办公城市、人员或作息通过标准考勤组、班组、班次版本及有期限的适用关系解决，不建立隐藏的单员工硬编码例外。

### 3.2 统一规则配置模型

考勤、假期、时间账户等相关规则尽量做成通用 HR 系统式的可配置能力，但必须使用受控字段和枚举，不允许任意脚本，也不得把默认值散落硬编码在计算逻辑中。

统一支持：

- 策略模板、策略版本、草稿、校验、发布、停用和回滚；
- 公司、地点、考勤组、政策组等作用范围；个人特殊情况通过加入有有效期的专用组处理；
- 生效日、失效日、优先级、冲突检测、发布前影响预览和样例试算；
- 版本快照、变更原因、操作人、操作时间和审计；
- 已月结/冻结期间保护。新规则不得静默改写已冻结结果；重开和重算必须保留版本、差异及审计。

### 3.3 班组、班次与考勤计算

1. 夏令时、冬令时通过考勤组下的班次版本和生效日期管理，不写死为固定“夏令组/冬令组”。
2. 所有考勤组默认启用晚餐扣除；启用开关、扣除窗口、扣除时长、触发条件以及工作日/周末/法定节假日的适用范围均可配置。
3. 每名员工每个自然月默认有 1 次迟到宽限机会。默认命中条件为迟到大于 0 且不超过 15 分钟；超过 15 分钟不消耗该机会。次数、分钟阈值、统计周期、作用范围、跨组处理和命中顺序均可配置；默认跨考勤组不重置当月已使用次数。
4. “单边缺卡”指某个计划工作段只有上班卡或只有下班卡。补卡期限内标记为待补正；逾期且无有效、按规则及时提交的业务单据时，默认仅将缺卡对应工作段计为旷工，不默认整日旷工。补正期限默认 7 个自然日；期限口径、逾期结果、受影响范围和是否允许管理员修正均可配置。
5. 外出、请假、补卡、出差、加班等单据必须进入统一证据链，并明确优先级、时间重叠切分、跨日、撤销和补录规则。
6. 加班餐扣默认适用于所有班组；工作日、周末、节假日可以分别配置扣除窗口和时长。
7. 加班申请逾期规则、跨日加班、第二天首次打卡、义务加班、临时后补加班等均以类型化规则表达，并覆盖边界测试。

### 3.4 假别与年假

1. 所有假别均可配置：计量单位、默认计算口径、最小申请单位、资格、所需材料、发放方式、有效期、结转、失效、销假、冲突、取消和余额规则；默认按工作日计算。
2. 年假资格与年假档位必须分开建模：
   - 资格门槛：最新任职周期在本公司连续任职满 1 年后才取得年假资格；该规则必须可配置，默认启用，默认 12 个完整日历月。
   - 档位依据：累计工龄，而不是只看本公司工龄。累计工龄 = 最新任职周期的本公司工龄 + HR 维护的入职前累计工龄。系统不建设公司外工龄证明审核流程，但所有维护和导入必须审计。
3. 默认年假档位：
   - 累计工龄满 1 年且不足 10 年：5 天 / 40 小时；
   - 累计工龄满 10 年且不足 20 年：10 天 / 80 小时；
   - 累计工龄满 20 年：15 天 / 120 小时。
4. 年假默认在最新一次入职周年日发放，有效至下一周年日前一天；二次入职从最新入职日重新计算资格和周年周期。
5. 周期内累计工龄跨档时，默认不在周期中途补差，在下一次周年发放时采用新档位；该行为应配置化。
6. 闰日入职、周年日前一日、周年日、到期日、离职、再入职、规则切换和冻结期间必须有明确、可测试的口径。

### 3.5 时间账户与期初数据

1. 必须支持员工期初工时、调休、年假等时间账户余额的 Excel 导入。
2. 导入须包含模板、字段校验、员工匹配、单位换算、预检、错误行下载、幂等、防重复发布、批次状态、余额流水和审计。
3. 余额不能只保存可覆盖的最终数值，必须有来源、发生额、余额、业务日期、有效期和冻结信息。

### 3.6 离线/异构考勤机打卡 Excel 导入

1. 新增“考勤打卡 Excel 导入”，用于无网络地点、无法连接 API 的设备、非得力或不同型号考勤机。它与组织期初导入、时间账户期初余额导入是三个不同功能。
2. 导入对象只能是考勤机原始打卡流水，不能导入迟到、早退、缺卡、旷工或加班时长等计算结果，也不能用来绕过补签申请。
3. 得力 API、设备 Excel 和 OA 考勤业务单据统一进入“原始事实层 → 标准化/匹配层 → 有效事件层 → 考勤计算层”，不得建立两套考勤算法。
4. 必须提供可下载、版本化的标准 `.xlsx` 模板，至少包含打卡数据、设备人员映射、字段说明、枚举、填写说明和合成示例。已交付参考模板为 `outputs/attendance-import-template-v1/神州HR_考勤打卡导入模板_V1.0.xlsx`，字段规则见 `docs/v1.9-rebaseline/03-attendance-punch-excel-import.md`。
5. 标准字段至少覆盖：场地编码、设备厂商/型号/编号、设备人员编号、员工工号、员工姓名（只核对）、打卡时间、方向、验证方式、原始记录 ID、原始事件码、时区和备注。姓名和部门不能作为唯一匹配键。
6. 不同厂商原始 `.xlsx` 通过字段映射和可保存的“厂商/型号/地点映射方案”兼容；首期不得只写死得力导出格式。旧 `.xls`/CSV 是否支持需在取得真实样本后明确。
7. 流程必须包含模板下载、来源地点/设备/时区选择、上传、字段映射、设备人员/员工匹配、预校验、跨来源去重、错误报告、影响预览、二次确认、发布、批次详情、作废/冲正和审计。
8. 文件级使用文件哈希幂等；记录级优先使用原始记录 ID，没有时用场地、设备、设备人员/员工、标准化时间和方向生成稳定指纹。Excel 与得力 API 必须跨来源查重，所有原始证据继续保留。
9. 必须保存批次号、原文件、文件哈希、模板/映射版本、原始行号、原始值、标准化值、匹配结果、错误码、导入人、发布人、request_id 和规范事件 ID，禁止静默丢弃或覆盖原始记录。
10. 已月结/冻结期间允许上传和预检，但默认禁止直接发布或静默重算；必须先按权限重开期间，再发布和重算，并保留新版本及差异审计。
11. 上传、预检、发布、作废/冲正、查看原始文件、查看原始行和下载错误报告分别鉴权，并受组织/地点数据范围限制。
12. 默认单文件 20MB、50,000 行，默认时区 `Asia/Shanghai`，近似重复窗口默认 60 秒；这些为受控系统参数。默认严格发布，存在阻断错误时不可发布；可以配置仅发布有效行，但必须明确确认并生成部分成功批次。

### 3.7 薪资预留

1. 薪资属于 P0-B，可做服务端领域和数据模型预留，但不能阻塞考勤 P0-A 验收。
2. 当前前端完全不展示薪资：默认关闭 feature flag，不注册可发现菜单、路由、首页卡片、全局搜索、导出入口或普通 API 能力。
3. 服务端采用独立 `PAYROLL` 权限域并默认拒绝。禁止先返回薪资数据再仅靠前端隐藏。
4. 若实施薪资后端，必须使用冻结的考勤快照、独立权限、审计和最小数据暴露；本期不生成银行付款文件。

## 5. 后续实施总原则

只有在人工确认 `docs_confirm` 后才可以进入实现。每一波必须单独授权并完成一个可运行的纵向切片：契约、V3+ 迁移、后端、权限、前端状态、自动化测试、说明和实际构建同步完成。不得一次性实现整个 PRD，也不得提前进入下一波。

推荐波次：

1. 本地账号密码、会话、权限和版本化规则配置底座；
2. 组织/员工 Excel 期初导入、本地维护、任职周期和累计工龄；
3. 考勤组、季节班次、日历、地点、晚餐扣除、迟到宽限和单边缺卡配置；
4. 得力在线打卡、离线/异构考勤机 Excel 与 OA 考勤业务单据只读接入，统一原始证据、字段映射、跨来源幂等、去重和水位；
5. 考勤计算、异常、补正、跨日、重算、月结和反月结；
6. 假别、周年年假、时间账户、期初余额导入和报表；
7. 员工自助、管理看板、响应式适配和 Open Design 收敛；
8. 默认关闭且前台不可发现的薪资后端预留；
9. 安全、性能、备份恢复和上线验收。

每一波完成后必须报告：实际改动文件、迁移、测试命令及真实结果、人工验证入口、未验证项和下一波建议，然后停止等待确认。未实际执行的验证不得写成“通过”。
