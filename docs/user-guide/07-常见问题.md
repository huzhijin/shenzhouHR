# 07 常见问题

## 为什么公司会自动选中？

当前账号只有一家授权公司时，系统会自动选择，减少重复操作。这不表示系统中只能有一家公司。

## 为什么我看不到另一家公司？

公司列表只显示当前账号有权管理的正式公司。请让系统管理员检查账号的公司数据范围，不要通过新建同名公司解决。

## 为什么出现英文测试公司？

本轮版本会停用并隐藏验证公司。若正式使用界面仍出现英文测试或验证公司，请停止选择该项，并联系部署管理员检查数据库和部署版本。

## 几个一级组织是不是几家公司？

不一定。一级组织只是组织树的第一层，可能是事业部、中心或部门。系统不会自动把一级组织拆成公司；是否为独立公司必须依据正式公司资料确认。

本轮业务已经确认上海昇州、上海晟州聚能、江苏神州和江苏芯越是 4 家独立公司，因此系统应在当前账号获得相应授权后显示 4 个公司选项。公司名称仍可作为各自组织树的根节点，但根节点不会替代公司记录。

## 为什么共享地点不再按公司分别新建？

地点是集团级物理主数据，全集团只有一套扬州、成都、大连、上海、合肥、武汉、深圳。公司只是与共享地点建立“可使用”关系，不应为 4 家公司重复创建 4 份同名地点。

在班次、日历、考勤组和人员归属页面仍要先选择公司，因为这些配置按公司隔离；在共享地点主数据区域则只显示 7 个地点。普通公司管理员可以在本公司配置中选择已关联地点，只有具备相应系统级权限的管理员才能修改会影响多家公司的共享名称或时区。

底层会为“4 家公司均可使用 7 个地点”保存 28 条可用关系。这些是关联，不是 28 条地点主数据，也不会要求重复维护名称和时区。

## 为什么员工已经导入，却不能登录？

员工档案与登录账号是两类数据。进入“账号管理”，使用“从员工批量开通”为需要登录的员工创建账号。

## 新账号的登录名是什么？

通过员工批量开通时，登录名默认使用工号。系统会忽略登录名前后的空格并统一字母大小写，但仍应按员工档案中的工号录入，避免混淆相似字符。

## 新账号为什么提示必须修改密码？

这是正常的安全要求。每个账号使用独立临时密码，首次登录后必须设置自己的新密码。

## 批量开通账号时为什么有员工被跳过？

常见原因包括：

- 已经存在绑定账号；
- 工号重复或登录名冲突；
- 员工不是在职状态；
- 没有当前有效任职；
- 员工不在当前公司或管理员权限范围内。

根据预检中的中文状态处理后，只重新提交仍显示“可开通”的员工。

## 忘记密码或提示用户名、密码错误怎么办？

依次检查：

1. 登录名是否为正确工号；
2. 是否混淆数字、字母或其他相似字符；
3. 临时密码是否已使用过；
4. 账号是否被锁定；
5. 是否需要管理员重置密码。

不要连续大量尝试，也不要把密码发给他人协助测试。

## 为什么登录提示“网络连接不可用”“登录服务暂时不可用”或“登录请求未被接受”？

两者含义不同：

- “网络连接不可用”表示浏览器没有收到服务器响应，检查本机网络、访问地址、Nginx 和防火墙；
- “登录服务暂时不可用”表示服务器已响应 5xx，通常需要系统管理员检查后端、数据库、迁移和服务日志。
- “登录请求未被接受”表示服务器返回了非预期 4xx，通常需要检查 CSRF、请求格式、反向代理规则或会话配置；它不等于密码错误。

不要因为出现服务端错误就重复尝试密码，也不要把 5xx 当成账号密码错误。记录发生时间和访问地址后交给系统管理员排查。

## 为什么部门负责人和部门主管看起来一样？

本轮版本统一使用“部门负责人”。“制造中心主管/主任”已移除，不再单独分配。管理员可以为部门负责人添加多条“公司＋部门”范围，因此同一个人可以负责其他公司的指定部门；每条范围都可以单独决定是否包含下级部门。

## 为什么看不到某个菜单或员工？

通常是角色或数据范围限制。先核对当前公司，再让管理员检查账号角色、组织范围和授权有效期。

## 为什么员工没有考勤结果？

依次检查：

1. 员工在目标日期是否处于有效任职；
2. 是否有当前有效考勤组归属；
3. 考勤组的班次和日历是否已发布并覆盖该日期；
4. 打卡或 OA 数据是否已同步；
5. 来源记录是否匹配到正确工号。

## 为什么已经有成都、上海等地点，员工仍按扬州时间？

地点和班次是两类配置。全集团共享扬州、成都、大连、上海、合肥、武汉、深圳 7 个地点，但只有经过批准的江苏神州大连 13 人、成都 4 人和上海张静进入特殊考勤组。其他人员即使业务上位于某个预置城市，只要没有调整考勤组，就继续使用所属公司的扬州默认冬夏令时间。

需要改变时，先发布目标班次，再从明确生效日起把员工调整到对应考勤组。不要仅改地点名称来改变上下班时间。

## 期初地点、班次和规则以后能修改吗？

可以修改已经接入的配置，但要按类型处理。地点名称、班次、工作日历、考勤组、人员归属，以及用餐扣除、迟到宽限、每月迟到豁免 3 类规则采用版本或修订记录。修改未来安排时创建后续版本，填写生效日和原因，完成校验、影响预览及发布。已经发布并用于历史核算的版本不能原地覆盖。

共享地点改变时区会影响所有关联公司。尚未投入考勤使用的地点可由具备完整权限的管理员创建后继修订；已有班次、日历、考勤组或历史引用的地点会被系统拒绝直接改时区，需要联系系统管理员评估受控迁移。早退、缺卡与补签、打卡归属与配对、加班认定、出勤率 5 类目前只有数据库起步记录，尚未开放为可维护、可解析的运行规则。

## 为什么规则已经修改却没有生效？

检查规则是否仍为草稿、是否完成发布、是否绑定到正确考勤组，以及生效日期是否已经到达。还要确认当前公司正确。

## 为什么考勤规则没有编辑按钮或保存不了？

按以下顺序检查：

1. 当前账号是否具有考勤策略管理能力和目标公司的有效范围；
2. 页面顶部是否已经明确选择公司；
3. 当前规则是否为已发布历史版本——已发布版本不可原地编辑，应创建未来生效的后继草稿；
4. 是否填写了生效日、变更原因和该规则要求的完整参数；
5. 是否先保存草稿、再校验、发布，并把已发布版本绑定到考勤组；
6. 是否正在尝试早退、缺卡/补签、打卡配对、加班认定或出勤率等尚未开放完整维护链的规则。

当前可正式维护的是用餐扣除、迟到宽限和每月迟到豁免三类。其他类型即使数据库存在起步记录，也不能通过高级模板或手工 SQL 当作已经可编辑的生产规则。

## 人员导入预检失败怎么办？

下载错误行报告，按行修正阻断问题后重新上传并预检。预检失败不会修改正式员工或组织数据。

## 导入后发现错误能直接删除吗？

已发布数据通常保留历史记录，不能直接删除。使用页面提供的撤销或更正操作；如果数据已被后续业务使用，系统可能要求新增更正记录。

## 页面没有数据，是不是系统坏了？

先检查当前公司、筛选日期、数据范围和数据是否已经发布。仍为空时，再检查人员导入、考勤组归属和来源同步状态。

## 得力已经填了 API 密钥，为什么没有打卡？

密钥只是一个条件。还要确认租户已初始化、来源已按公司注册、员工绑定已确认、目标期间允许写入、同步任务已运行且记录没有进入隔离。当前正式员工绑定和自动调度管理尚未闭环，不能承诺填入密钥就自动显示。

## OA 数据库已经连通，为什么没有单据？

当前只读连接和人员工号查询不等于六类 OA 业务单据已同步。必须先签字确认真实表、主从键、审批/撤回状态、枚举、时区和增量水位，再实现固定 SQL 和同步任务。连接数据库本身不会把任意 OA 表直接显示到页面。

## 为什么有年假策略却没有年假余额？

年假策略、累计工龄和年假余额是三类数据。策略决定资格和发放，累计工龄参与档位判断，余额来自不可变时间账户台账。当前期初余额导入尚未开放，不能拿累计工龄代替余额，也不能手工更新数据库余额。

## 为什么已有原始打卡，首页和报表仍为空？

原始打卡还要经过人员匹配、考勤配置解析、每日计算、异常处理和正式投影发布。报表只读 `PUBLISHED` 投影，首页还要求投影足够新。当前自动发布链尚未完整接通，因此“有原始数据”不等于“已正式出数”。

## 为什么报表中的公司比考勤设置页面少？

报表公司下拉框只显示所选月份已有可见、已发布报表投影的授权公司。某家公司已在考勤设置中存在，但该月还没有发布报表投影时，不会出现在报表公司列表中。这不是公司资料丢失。

## 什么时候需要联系管理员？

遇到以下情况时，记录操作时间、页面名称和关联编号后联系管理员：

- 正式界面出现测试公司；
- 公司或组织数据疑似跨范围显示；
- 批量任务长时间停留在处理中；
- 同一员工出现多个当前考勤组；
- 页面反复提示无权限但授权已确认；
- 重置密码后仍无法登录。

提供问题信息时不要附带真实密码或整份员工敏感数据。
