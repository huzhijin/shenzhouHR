# 12 分角色使用说明

## 适用角色

当前系统预置六个正式角色：系统管理员、HR 管理员、高管、部门负责人、员工本人、审计只读。角色决定能做什么，数据范围决定能看哪些公司、部门或本人数据；两者缺一不可。

最初需求中的“考勤专员/考勤主管”当前没有拆成独立角色，相关运营职责主要合并到 HR 管理员。若客户要求制单、复核、发布、月结相互分离，需要另行确认职责分离矩阵，不能给所有操作人员系统管理员权限。

## 一、所有用户共同操作

### 首次登录

1. 使用系统管理员安全交付的本地账号和临时密码；
2. 首次登录按提示设置 12～256 位强密码；
3. 不在共享电脑保存密码，不把临时密码发到群聊；
4. 登录后核对姓名、菜单和可见公司/部门；
5. 权限过大、过小或公司不对时立即退出并联系管理员。

“网络连接不可用”只表示浏览器确实未连到服务；后端 5xx 会提示“登录服务暂时不可用”；非预期 4xx 会提示“登录请求未被接受”。遇到这些提示时保留发生时间，由系统管理员检查网络、代理、服务和数据库，不要连续反复提交密码。

### 数据安全

- 只查看职责范围内的数据；
- 不通过截图、个人网盘或公开群传递员工明细；
- 离开电脑时退出或锁屏；
- 发现账号异常、数据串公司或导出泄露时立即报告；
- 不让 DBA 通过手工改表代替页面/API 的正式流程。

## 二、普通员工（员工本人）

### 主要职责

- 查看本人今日考勤工作台；
- 核对班次、首末打卡、当日状态和本人待处理异常；
- 在功能正式接通后查看本人月度记录、假期余额和反馈进度；
- 对错误结果提交本人反馈或按公司流程申请补签。

### 推荐日常步骤

1. 登录“我的考勤工作台”；
2. 核对今日班次、打卡和异常；
3. 发现问题先记录业务日期和实际情况，不修改原始证据；
4. 使用反馈/补签入口或联系 HR；
5. 月底核对本人汇总和已处理异常。

### 当前版本限制

本人今日工作台已有正式接口，但依赖本人身份绑定和新鲜的正式投影。“我的考勤记录”“我的假期”“反馈中心”在生产网关仍未全部接通；演示模式能显示不代表客户生产可用。年假期初台账未完成前，员工不能把页面空余额视为真实零余额。

普通员工只能使用 `SELF` 范围，不能查询其他员工，也不能获得报表导出能力。

## 三、部门负责人

### 主要职责

- 查看明确授权部门及按需包含的下级部门；
- 查看部门员工、今日异常、请假和正式报表；
- 跟进缺卡、迟到、待补材料和待复核事项；
- 把制度或人员主数据问题反馈给 HR，不直接修改全公司配置。

### 推荐步骤

1. 核对页面显示的公司、部门及“包含下级部门”范围；
2. 每日查看异常工作台，优先处理阻断异常；
3. 按月份查看部门报表，核对异常数量和员工明细；
4. 对待补材料事项联系员工，对制度问题交由 HR；
5. 月结前确认部门待处理事项已清零或有书面处置。

部门负责人不因角色名称自动看到全公司。员工调岗后，权限按查询时的当前任职重新解析；原负责人不能继续看到已调走员工的当前明细。默认没有导出能力。

## 四、HR 管理员

### 上线初始化

1. 逐公司核对组织树、员工和任职；
2. 按需导入累计工龄，注意它不是年假余额；
3. 核对地点、班次、工作日历和考勤组；
4. 给每名应考勤员工建立唯一有效考勤组归属；
5. 校验并发布已接入的三类规则；
6. 与系统管理员完成账号、角色和数据范围；
7. 与实施方完成得力/OA/期初余额及报表口径验收。

### 每日操作

1. 检查来源状态、最近同步时间、匹配和隔离数量；
2. 检查今日工作台和阻断异常；
3. 处理缺卡、迟到、请假、补签和人员/配置冲突；
4. 抽样对照原始依据与计算结果；
5. 记录无法当天处理的原因和责任人。

### 每月操作

1. 检查全月员工/日期覆盖率和来源水位；
2. 处理未决异常和 OA 撤回/修改；
3. 核对年假/调休台账；
4. 运行或确认受控计算和正式投影发布；
5. 核对九类报表、公司/部门汇总和同版本导出；
6. 按批准流程冻结、月结或重开期间；
7. 留存对账和审批证据。

当前自动计算/发布、OA 单据、年假期初、离线打卡导入还没有完整生产闭环。HR 不应通过手工改库“补出”首页或报表。报表导出应填写真实用途并安全保管文件。

## 五、高管

### 主要职责

- 查看明确授权公司或组织的工作台和汇总报表；
- 关注出勤率、异常、工时、加班、请假、未结算和数据新鲜度；
- 从汇总穿透到同一正式投影的明细；
- 对异常趋势和制度问题提出管理要求。

高管首次授权可以由管理员预填当前可授予公司，但保存前必须复核；后续新增公司不会自动扩权。默认只读且无导出权限。当前综合驾驶舱尚未完整达到最初指标范围，高管看到空白时应先核对投影与数据新鲜度，不能把空白解释为零异常。

## 六、系统管理员

### 主要职责

- 安装、升级、备份、恢复、监控和日志诊断；
- 创建首个管理员，维护账号状态、密码重置、角色与范围；
- 管理应用环境、密钥引用、HTTPS、数据库和外部来源开关；
- 验证 Flyway 版本、健康检查、最小权限和审计；
- 配合 HR 发布需要系统级审批的共享配置；
- 处理服务不可用、端口、反向代理、数据库连接和任务失败。

### 安全边界

- 系统管理员不自动获得考勤报表读取权限，这是隐私最小授权设计；
- 需要参与业务验收时，应由有权人员额外授予明确公司范围，验收后撤销；
- 不使用 root 数据库账号运行应用；
- 不把得力/OA 密钥写入 Git 或命令行日志；
- 不修改已执行的 Flyway 迁移，不使用 `clean` 或无依据 `repair`；
- 不直接更新考勤结果、余额或投影表；
- 生产切流、数据迁移和外部初始化需单独审批。

### 服务不可用排查顺序

1. 查看浏览器请求状态，区分无网络、401/403 和 5xx；
2. 执行后端健康检查；
3. 查看 `systemctl status shenzhouhr` 和最近服务日志；
4. 检查 MySQL、Flyway 版本和连接池；
5. 检查 Nginx 反向代理和后端私有端口；
6. 只在保留现场、完成备份后执行批准的恢复或回滚。

## 七、审计只读

### 主要职责

- 查询账号、角色、规则、导出、同步、期间和关键操作记录；
- 核对操作者、时间、范围、原因和结果；
- 验证敏感操作没有明文密码、密钥或原始 OA/打卡载荷；
- 对越权、无原因调整、重复发布和异常导出提出整改。

审计只读默认不修改业务数据，也不因能查看审计记录而自动获得员工考勤明细。需要查看业务证据时必须取得明确范围和审批。

## 八、职责分离建议

| 操作 | 建议发起 | 建议复核/批准 | 系统执行 |
| --- | --- | --- | --- |
| 员工/任职批量导入 | HR | HR 负责人 | HR 管理员 |
| 规则变更 | 考勤经办 | HR 负责人 | HR 管理员发布 |
| 得力/OA 启用 | 系统管理员/实施方 | HR + IT/DBA | 系统管理员 |
| 期初余额导入 | HR 经办 | 薪资/HR 负责人 | 受控导入服务 |
| 月结/重开 | HR 经办 | HR 负责人 | 受控月结服务 |
| 敏感报表导出 | HR | 按客户制度 | 有导出权限账号 |
| 角色扩权 | 系统管理员 | 数据责任人 | 有授权范围的管理员 |

如果客户要求经办和复核必须是不同账号，应新增考勤经办、考勤复核或月结审批角色及状态机；当前六角色模型不能自动证明双人复核。

## 九、角色验收

每个角色至少测试：

- 能看到职责内菜单和数据；
- 看不到未授权公司、部门和员工；
- 不能执行职责外修改或导出；
- 多公司/多部门范围合并正确；
- 授权到期、员工调岗或账号锁定后立即失效；
- 所有关键操作有审计记录；
- 空态、服务不可用和数据未发布提示不会被误解为“零数据”。
