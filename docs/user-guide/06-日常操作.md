# 06 日常操作

## 每日建议顺序

1. 确认当前公司和业务日期。
2. 检查考勤来源或导入任务是否成功。
3. 查看考勤工作台中的人员数量和异常数量。
4. 处理缺卡、迟到、请假或来源冲突等异常。
5. 抽查报表，确认结果与原始依据一致。

## 在线考勤与 OA 数据

进入“考勤机数据”或“OA 单据”后，先核对来源状态和最近同步时间。已经配置且页面明确提供手动同步按钮的考勤机来源，可以按以下步骤操作：

1. 确认当前公司和数据时间范围；
2. 发起同步；
3. 可离开页面，稍后到“同步记录”查看结果；
4. 失败时查看中文错误说明和关联编号，再决定重试或联系管理员。

不要在上一次同步仍处理中时反复提交相同任务。OA 数据是否可以手动同步取决于实际接入方式；页面没有同步按钮时，不要套用考勤机操作步骤。

## 打卡文件导入当前状态

当前正式后端只具备打卡导入模板及导入任务、明细和错误信息的查询能力，上传、预检和确认发布的正式写入接口尚未开放。演示页面中的内存流程不代表可以写入正式数据库。

正式部署时不要使用该页面导入文件，也不要把文件直接写入数据库。待后端上传、预检、幂等和发布链路完成并通过验收后，手册会补充正式步骤。当前考勤事实应使用已经验收的考勤机或 OA 数据接入链路。

## 查看考勤工作台

工作台用于快速判断数据是否完整。建议重点查看：

- 应出勤人数与已产生结果人数；
- 迟到、早退、缺卡等异常数量；
- 是否存在整个部门或考勤组没有结果；
- 数据日期和更新时间是否符合预期。

工作台数字异常时，先检查数据来源、人员考勤组归属和工作日历，不要直接修改报表结果。

## 查询和导出报表

进入“考勤报表”后：

1. 选择报表类型和月份；
2. 多公司账号再明确选择公司，页面会自动加载；
3. 核对汇总数量和异常项；
4. 需要留档且有导出权限时，填写用途并完成当前密码复核；
5. 导出文件按公司敏感数据要求保存和传递。

部门负责人只能查看逐条授权的公司和部门；只有对应范围勾选“包含下级部门”时才会同时看到下级组织。同一账号可以具有多家公司下的多条部门范围，未明确授权的公司或部门仍不可见。

当前正式页面没有组织、员工筛选框，也没有单独“查询”按钮。公司列表只显示该月份已有可见、已发布报表投影的授权公司。

### 月度考勤颜色矩阵怎么看

在非演示模式下，选择“考勤明细”、月份和已有已发布投影的公司后，系统以“员工 × 日期”展示正式月度矩阵，每页 20 人。每个日期格可以同时显示首次打卡、末次打卡、班次和多个小型中文状态标签；这不是整格复制旧 Excel 填充色。

主要颜色与文字含义如下：

| 文字 | 颜色提示 | 含义 |
| --- | --- | --- |
| 迟到 | 珊瑚红 | 首次有效打卡晚于当天班次和宽限规则 |
| 早退 | 蓝色 | 末次有效打卡早于当天应下班时间 |
| 漏刷 | 紫色 | 应有的上班卡或下班卡缺失 |
| 旷工 | 红色系 | 按正式规则形成旷工异常 |
| 认可加班 | 绿色 | 已形成正式认可加班结果 |
| 调休、外出、出差、请假、补签 | 对应提示色 | 当天存在进入正式投影的有效单据或结果 |
| 休息日 | 中性提示色 | 当天正式日事实标记为休息日 |

颜色只帮助快速定位，格子中始终保留中文文字，不能只凭颜色下结论。同一天如果既有“迟到”又有“外出”或“补签”，系统会并列显示，不会用一种颜色盖掉另一种状态。

正式状态由已发布报表投影中的打卡时间、当天有效班次、工作日历、考勤规则、OA 单据和异常事实计算；Excel 单元格颜色不参与计算，也不能直接修改报表结果。截图中的旧表颜色可作为展示样式参考，但如果某个历史 Excel 只有颜色、没有时间或状态文字，必须先提供原始工作簿并确认每一种填充色的业务含义，再制作专用导入模板；不能根据截图猜测后直接入账。

只有进入该月正式投影事实的员工才会出现在矩阵中；系统不会仅凭员工档案为完全没有事实的人员生成空白行，空白周末也不会自动变成“休息日”。查询结果为空时，先检查该月份是否已有已发布报表投影，再检查公司、人员考勤组、打卡来源和 OA 数据。如果页面明确显示“客户演示数据”，看到的不是正式计算结果。

颜色矩阵与受控导出使用相同的数据权限，切换公司后不会保留上一家公司的人员结果。系统还会逐项核对矩阵和平铺明细的投影版本、数据时间、来源版本、期间状态、时区、权限动作、范围和筛选条件；任一项不一致都会停止展示并禁止导出，提示刷新重试。

受控导出是同一正式快照的平铺考勤明细，不保留页面矩阵的颜色、中文标签样式或横向日期布局。需要留存当前视觉矩阵时应使用后续专用矩阵导出功能，不能把平铺明细误认为彩色表格。

## 调整规则或班次

规则、班次、日历和考勤组的调整都应填写明确的生效日期和原因。建议：

1. 新建后续生效版本；
2. 完成校验；
3. 查看影响范围；
4. 发布；
5. 用一名非敏感样例员工和一个样例日期验证；
6. 在“操作记录”中核对留痕。

不要为了修正未来配置而覆盖已经用于历史核算的版本。

## 员工入职、调岗和离职

- 入职：创建员工和任职，按需要开通账号，并分配考勤组。
- 调岗：新增或调整任职，检查部门负责人权限和考勤组是否需要变化。需要更换班次、地点或日历时，在原归属行点击“调配考勤组”，选择同公司的目标组、生效日并填写原因；系统从生效日起关闭旧归属、创建目标组后继，历史日期保持不变。不能调到其他公司，也不能回填已经过去的日期。
- 离职：结束任职并锁定账号，同时由管理员检查该员工后续日期是否仍被考勤组和报表纳入；当前页面没有独立的“终止考勤组归属”按钮。
- 二次入职：使用二次入职流程新增任职记录，不要重复创建员工。

## 操作完成后

每次批量导入、权限调整或规则发布后，至少核对一次：状态、数量、生效日期、适用范围和操作记录。
