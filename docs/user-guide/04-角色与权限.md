# 04 角色与权限

## 权限由两部分组成

账号能看到什么，由“角色”和“数据范围”共同决定：

- 角色决定可以使用哪些功能；
- 数据范围决定可以查看或管理哪些公司、组织或员工。

只分配角色但不设置正确范围，可能导致看不到数据或看到过多数据。

## 默认角色说明

| 角色 | 适用人员 | 常用数据范围 |
| --- | --- | --- |
| 系统管理员 | 负责账号、权限和系统管理的少数人员 | 按批准的管理范围 |
| HR 管理员 | 维护组织、员工和考勤配置的 HR 人员 | 公司 |
| 高管 | 查看授权范围内的工作台和报表 | 公司或组织 |
| 部门负责人 | 查看所选部门及允许的下级组织 | 组织 |
| 员工本人 | 查看自己的考勤、假期和反馈 | 本人 |
| 审计只读 | 查询操作记录，不修改业务数据 | 按批准的审计范围 |

系统不再提供“制造中心主管”或“制造中心主任”角色。原本需要此类权限的人员统一使用“部门负责人”，并选择对应组织范围。

## 为账号分配角色

1. 进入“账号管理”。
2. 查询并打开目标账号。
3. 进入“角色与数据范围”。
4. 选择符合实际职责的角色。
5. 按角色选择数据范围：本人、组织或公司。
6. 部门负责人应选择具体组织；当前系统的组织范围会自动包含该组织的下级组织。
7. 如为临时授权，填写开始和结束时间。
8. 保存后，重新打开账号详情核对授权结果。

授权应由有权管理该范围的管理员操作。系统拒绝越权授权时，不要通过扩大自己的权限绕过。

## 部门负责人能看到什么

部门负责人通常只能查看：

- 被授权组织中的当前在职员工；
- 该组织的下级组织及员工；
- 上述范围内的考勤工作台和报表。

部门负责人不等同于 HR 管理员，不能因为负责某个部门就自动获得全公司人员维护或系统配置权限。

## 最小授权原则

- 普通员工只分配“员工本人”。
- 部门管理人员优先分配“部门负责人”，不要直接给 HR 管理员。
- 只需查看操作记录的人员使用“审计只读”。
- 系统管理员数量应尽量少，并定期复核。
- 工作职责变化、调岗或离职后，应立即调整或结束授权。

## 授权后验证

建议使用不含真实业务数据的测试方法验证：

1. 让目标用户重新登录；
2. 确认菜单与职责一致；
3. 确认只能看到授权公司或组织；
4. 确认不能修改职责之外的数据；
5. 在“操作记录”中核对授权变更留痕。
