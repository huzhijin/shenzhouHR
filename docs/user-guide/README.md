# 神州 HR 客户使用说明

本手册面向普通员工、部门负责人、HR 管理员、高管、系统管理员和审计人员，说明上线准备、日常操作、外部数据接入、报表口径及各角色职责。

本手册适用于完成本轮简化升级后的系统版本。若页面上没有文中入口，请先确认部署版本和当前账号权限，不要使用其他相似按钮代替。

## 从哪里开始

首次部署建议按以下顺序操作：

1. 登录并确认当前管理公司。
2. 核对公司及组织树。
3. 导入或维护员工及任职信息。
4. 从员工批量开通登录账号。
5. 为需要管理权限的账号分配角色和数据范围。
6. 核对地点、班次、工作日历、考勤组及人员归属。
7. 核对考勤规则及其生效范围。
8. 导入或同步考勤数据，检查工作台与报表。
9. 完成计算、异常复核和正式投影发布，确认工作台及报表确实来自正式数据。

## 当前版本边界

手册会明确区分三种状态：

- “可操作”：正式页面、接口、持久化和权限链已经存在；
- “需联调”：代码骨架存在，但必须取得客户系统字段、真实样本或环境验证后才能启用；
- “待开发”：当前没有完整的生产写入或自动编排链，不能用手工改库、演示页面或测试数据代替。

连接数据库或拿到原始打卡，并不等于考勤结果、首页和报表会自动出现。正式展示还需要人员匹配、考勤配置、确定性计算、异常处理、期间状态和正式投影发布。具体见第 09～11 章。

## 四个重要概念

### 公司

公司是系统中的最高数据边界。切换公司后，组织、员工、考勤组和规则等页面只应显示当前有权管理的公司数据。

### 地点

地点是集团共享的物理主数据，不属于某一家公司的独立副本。全集团只维护一套名称和时区；公司通过可用关系选择地点，班次、日历、考勤组和人员归属仍按公司隔离。

### 组织

组织是公司内部的部门、中心或团队，可以组成多层树形结构。一级组织不等于公司，系统不会因为组织位于第一层就自动把它拆成独立公司。

### 账号

员工档案用于记录人员和任职信息；账号用于登录系统。员工导入完成后，还需要为需要登录的员工开通账号。

## 使用约定

- 页面入口会根据当前账号权限自动显示；看不到某个菜单时，先检查角色和数据范围。
- “保存草稿”通常不会让配置立即生效；需要发布的页面必须完成校验和发布。
- 所有生效日期、结束日期和适用范围都应在提交前复核。
- 不要在截图、聊天、邮件或手册中记录真实密码、员工身份证号、手机号等敏感信息。
- 操作完成后，以页面成功提示、列表状态和业务结果为准，不要反复点击提交。
