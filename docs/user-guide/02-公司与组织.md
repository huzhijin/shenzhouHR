# 02 公司与组织

## 公司和组织有什么区别

- 公司：用于隔离人员、权限、考勤配置和报表数据。
- 组织：公司内部的部门、中心、车间或团队，可以有多层上下级关系。

一个公司可以包含多个一级组织。一级组织的数量不能用于判断系统中有几家公司，也不能据此自动生成公司记录。是否属于独立公司，应以正式业务确认的数据边界为准。

本轮已经确认并按 4 家独立公司管理：

- 上海昇州半导体科技有限公司；
- 上海晟州聚能半导体科技有限公司；
- 江苏神州半导体科技股份有限公司；
- 江苏芯越半导体科技有限公司。

四家公司分别隔离组织、员工、考勤配置、权限和报表。原始导入批次涉及四家公司，为了保留原文件和发布记录的完整审计链，旧的混合导入所属公司只作为停用的历史归档存在，不会出现在日常公司选择器中，也不能继续录入业务数据。

## 选择当前公司

1. 查看页面顶部或表单中的“公司”。
2. 只有一家授权公司时，系统自动选中，并提示“当前账号仅授权 1 家公司”。
3. 有多家授权公司时，下拉框保持可用，必须明确选择本次要管理的公司。
4. 确认公司全称无误后，再维护组织或员工。

公司选项可附带公司代码用于区分，但应以中文公司全称为主要识别信息。

如果明明负责多家公司却只能看到一家，先让系统管理员检查该账号的公司数据范围。不要在组织树中新增同名节点，也不要为了让下拉框出现选项而重复新建公司。

### 公司主数据如何维护

当前版本没有单独的“公司管理”页面。正式公司由初始化或受控部署脚本建立；“部门与组织”里的“新建组织”只会新增公司内部的组织节点，即使组织名称带“公司”，也不会变成可切换的公司。

需要新增或修改正式公司时，应由系统实施人员按公司编码、中文全称、生效日期和数据隔离要求执行受控变更。变更完成后必须同时复核：

- 公司是否出现在有权限账号的公司选择器中；
- 组织、员工、考勤配置和报表是否仍按公司隔离；
- 高管及其他跨公司账号是否需要手动补充新公司的数据范围。

## 查看组织树

进入“部门与组织”页面后，从左到右或从上到下查看组织层级。建议重点核对：

- 每个组织的名称和编码；
- 上级组织是否正确；
- 部门、中心、团队之间的层级是否正确；
- 是否存在同名但实际不同的组织；
- 已停用组织是否仍被用于新任职或新授权。

## 新增组织

1. 进入“部门与组织”。
2. 点击“新建组织”。
3. 在弹窗的“公司”中选择该组织真正所属的公司。
4. 填写组织编码、组织名称、组织类型和生效日。
5. 选择上级组织；创建根组织时按页面要求留空或选择公司根节点。
6. 填写不少于 4 个字的清晰变更原因。
7. 点击“确定”，再在组织树中核对公司归属、完整路径和状态。

不要仅凭名称判断上级组织，提交前应同时核对完整层级路径。

## 调整组织

1. 进入“部门与组织”，在左侧组织树中选中目标节点。
2. 在右侧详情中点击“编辑组织”。
3. 按实际业务调整上级组织、组织编码、组织名称、组织类型或状态。
4. 核对生效日；需要在未来失效时填写失效日，否则保持长期有效。
5. 填写清晰的变更原因，点击“确定”。
6. 刷新页面，在组织树和右侧详情中复核新名称、上级、状态及生效区间。

修改前应先确认：

- 是否会影响员工当前任职；
- 是否会影响部门负责人权限范围；
- 是否会影响考勤组或报表筛选；
- 生效日期是否符合实际业务日期。

系统保留历史记录时，应通过页面提供的调整操作新增生效版本，不要试图删除历史数据。

## 停用组织

停用前先处理该组织下的在职员工和仍有效的权限。建议顺序为：

1. 将员工调整到新的任职组织；
2. 调整部门负责人等组织范围权限；
3. 检查该组织是否仍被考勤或报表使用；
4. 最后停用组织。

## 完成后的核对

- 组织树没有断层或循环；
- 员工所在部门与实际一致；
- 部门负责人只能看到逐条授权的公司和组织；每条组织范围按配置决定是否包含下级组织；
- 切换公司后不会看到其他公司的组织和员工。
