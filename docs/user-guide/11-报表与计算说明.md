# 11 报表、工作台与计算说明

## 一、先回答“有数据是否就可以显示并计算”

不可以只看数据库是否有记录。正式报表查询只读取指定公司、月份最新的 `PUBLISHED` 不可变投影。没有投影时，接口会返回“当前期间尚无已发布的报表投影”，页面不会拿原始打卡临时计算。

完整出数条件包括：

1. 数据库已按 V1～V31 完成迁移；
2. 公司、员工、当前任职和组织版本有效；
3. 每名应考勤员工在业务日能唯一解析地点、班次、日历、考勤组和规则；
4. 得力、OA 或其他来源已同步，人员唯一匹配，未知记录已隔离；
5. 全月每日结果和当前异常状态已经确定性计算并持久化；
6. 请假/OA、年假/时间账户具有同一快照时点的正式事实；
7. 期间状态、来源水位、计算版本和覆盖率通过发布门禁；
8. 受信任的服务端流程发布正式投影；
9. 当前账号具有报表能力和覆盖目标公司/组织/本人的有效数据范围。

当前第 5～8 步尚未形成完整的自动生产编排。因此现阶段不能承诺“客户库一连、数据一放进去，首页和报表就自动出现”。

## 二、当前九类正式报表

| 页面名称 | 代码 | 当前事实与公式 | 生产就绪条件 |
| --- | --- | --- | --- |
| 考勤明细 | `ATTENDANCE_DETAIL` | 员工日的应出勤、确认工作、认可加班、请假、旷工、实际工作、迟到、早退、缺卡和首末打卡 | 授权员工整月日结果完整 |
| 请假统计 | `LEAVE` | 生效 OA 请假/调休单据；按与所选月份重叠的半开区间纳入 | OA 状态、主从键、时区、撤回链签字并同步 |
| 加班统计 | `OVERTIME` | 按工作日、周六、周日、法定节假日汇总认可加班 | 班次、日历、加班审批和餐扣规则正确 |
| 月工时统计 | `WORK_HOURS` | 实际工作分钟 = 排班内确认工作分钟 + 认可加班分钟 | 日结果完整 |
| 考勤异常总览 | `EXCEPTIONS` | stable case 的当前状态和安全证据摘要 | 异常 current state 已持久化和复核 |
| 迟到统计 | `LATE` | 迟到事件数、原始迟到分钟、计罚迟到分钟 | 日结果和月度豁免已完成 |
| 未打卡统计 | `MISSED_PUNCH` | 单边缺卡次数；待补正/超期由异常状态表达 | 补卡等待期及 OA 补签已处理 |
| 出勤率统计 | `ATTENDANCE_RATE` | 当前运行代码暂为排班内确认工作分钟 ÷ 应出勤分钟 | 必须先解决本章公式冲突 |
| 年假统计 | `ANNUAL_LEAVE` | 期初 + 发放 + 加班转入 + 人工增加 − 使用 − 到期 + 撤销返还 − 人工扣减 | 时间账户台账和不可变月快照接入 |

九个报表名称已经存在，不代表九个数据来源都已生产就绪。请假和年假尤其依赖尚未完成的 OA 适配与时间账户链。

## 三、当前页面可以怎样查询

- 选择报表类型和月份；
- 多公司账号明确选择公司，单一可见公司自动选中；
- 异常报表可以选择全部、待处理、待补充材料、待复核或已处理；
- 普通报表和月度考勤矩阵应通过上一页/下一页查看全部结果；
- 查询和导出都必须由后端再次按当前账号范围过滤；
- 月度矩阵和平铺明细的投影版本、来源版本、数据时点、期间状态、范围和允许动作不一致时停止展示；
- 页面明确展示数据版本、来源版本和计算公式版本；当前出勤率命中暂行公式时会显示待业务签字提示；
- 导出必须绑定当前页面的投影版本、查询指纹、范围、筛选和字段白名单；期间发布新版本后，旧页面不得静默导出新版本。

当前尚缺业务友好的组织树和员工选择器。后端虽然接受组织/员工筛选，但页面不能要求客户手工填写数据库 UUID。需要复用授权组织树和公司内员工目录后再开放。后端当前还会先把整月事实读入 Java、完成全部聚合后再截取一页，属于内存分页；大公司正式验收前应改为数据库侧或预聚合分页，并完成容量测试。

## 四、导出规则

- 只有具有导出能力的角色才能创建和下载；默认只有 HR 管理员具备；
- 创建和下载均要求当前密码复核；
- 导出范围不能大于当前页面及账号授权范围；
- 字段使用服务端白名单，不能导出内部引用、公式版本或原始敏感载荷；
- 5 万行以内同步生成，超过 5 万行进入异步队列；
- 下载时重新校验当前权限、投影、可见内容摘要、文件长度和 SHA-256；
- 撤权、员工调动、投影变化、任务过期或文件校验失败后，旧文件不可下载；
- XLSX 的“口径说明”页记录导出编号、主体、用途、完整筛选、授权范围摘要、查询/内容摘要、投影/公式/来源版本、数据时点、期间状态、创建/生成时间和实际字段顺序，便于复核同一文件的来源；
- 当前正式格式为 XLSX。数据库预留其他格式不等于页面已经支持；
- 平铺导出不保留页面月度矩阵的颜色、标签样式和横向日期布局。

导出文件含员工敏感数据。客户应确定保存期限、加密传输、收件范围和销毁责任人；系统生成成功不等于可以通过个人邮箱或公开群传递。

## 五、首页考勤工作台为什么没有数据

当前管理工作台主要展示今日异常：未处理异常、影响员工、阻断异常、近七日趋势以及按严重度、类型和组织排行。它需要当日正式投影且 `dataAsOf` 至少达到业务日零点；否则会提示数据未准备好。

最初需求中的完整管理驾驶舱还包括：

- 出勤率、异常率；
- 确认工作、认可加班、请假；
- 未结算数量、数据新鲜度；
- 公司、组织、考勤组和本人范围；
- 小样本抑制；
- 从指标严格穿透到同版本报表。

这些综合指标和考勤组范围当前未完整接入正式工作台。正式“考勤大屏”路由目前只在演示模式开放，不能把演示大屏当作生产交付。客户需要确认是恢复完整驾驶舱，还是正式把范围缩减为“今日异常看板”。

## 六、与最初报表需求的对照

| 最初需求 | 当前状态 | 后续动作 |
| --- | --- | --- |
| 日报、周报、月报 | 当前九类查询均以自然月为期间；考勤明细含每日事实，但没有独立日报/周报模式 | 确认日报/周报的字段、截止时间、补数和历史重算 |
| 部门/班组汇总 | 事实保留发生时组织，后端支持组织过滤；缺正式组织/考勤组聚合页和选择器 | 确认汇总层级、调岗归属及组口径 |
| 公司综合指标 | 只有部分报表和今日异常工作台 | 补出勤率、异常率、工时、加班、请假、未结算和新鲜度 |
| 部门/组指标 | 尚无完整驾驶舱 | 确认排班、确认工时、迟到、早退、缺卡、旷工、加班和余额风险公式 |
| 个人日/周/月 | 本人今日工作台可读；本人记录/假期生产网关未接通 | 接通本人正式投影，增加周/月视图 |
| 九类正式报表 | 查询/计算框架存在 | 补齐来源、自动发布、完整性门禁和业务签字 |
| 查询穿透 | 工作台入口、平铺页、月度矩阵和后续分页已绑定同一投影版本；版本变化时拒绝混合展示 | 在真实 MySQL、客户授权范围和浏览器上验证跨页、撤权和并发发布负例 |
| 受控导出 | XLSX 已严格绑定页面投影、查询指纹、范围、完整筛选和字段白名单 | 在真实 MySQL 验证同步/异步、大文件、客户留存制度和故障恢复 |
| 大数据分页/性能 | 页面分页正在补齐；服务端仍为内存聚合后分页 | 改数据库/预聚合分页并做真实容量测试 |

## 七、正式投影发布必须增加的门禁

当前发布模型允许事实列表为空，仅凭非空来源版本也可能发布一个结构合法但内容不完整的投影。上线前必须定义并实现至少以下门禁：

- 授权范围内应计算员工总数和实际覆盖员工数；
- 期间内应计算员工日数量和实际日事实数量；
- 班次、日历、考勤组、规则无法解析数量；
- 得力/OA 等来源的期望水位、实际水位和滞后时间；
- 无法匹配、重复、未知状态和隔离数量；
- 阻断异常、待处理异常和允许带入报表的阈值；
- OA/年假来源未启用时是“不适用”还是“缺失”；
- `OPEN`、`FROZEN`、`CLOSED` 各自允许的完整度；
- 投影、计算、规则、人员、来源和台账版本摘要；
- 发布责任人、原因、时间和自动/人工触发类型。

没有这些门禁时，“空报表”无法区分“确实无人/无数据”和“同步或计算漏了”。

## 八、需要客户睡醒后确认的报表逻辑

### P0：确认后才能实现或上线

1. 出勤率到底是“实际出勤 ÷ 应出勤”还是 V30 文本中的“应出勤 ÷ 实际出勤”？后者可能超过 100%，请确认是否为文字写反。
2. 出勤率按分钟、小时、天数还是人次计算？迟到/早退是否减少实际出勤？
3. 带薪假是计入实际出勤分子，还是从应出勤分母扣除？事假、病假、年假、调休是否一致？
4. 零应出勤、零实际出勤分别显示 `N/A`、0% 还是 100%？
5. 公司/部门出勤率按总分钟加权、员工平均还是员工日平均？
6. 什么条件允许发布正式投影：必须覆盖哪些员工、日期和来源，允许多少隔离/阻断异常？
7. `OPEN` 月是否允许发布部分实时结果？`FROZEN/CLOSED` 是否必须全量且零阻断？
8. 正式投影采用每日定时、来源同步后、管理员手动刷新还是月结触发？各自 SLA 是什么？
9. OA 六类表的真实主从键、最终审批/撤回状态、稳定业务键、水位、时区和枚举是什么？
10. OA 单据跨任职/调岗时拆成多段，还是要求同一身份版本覆盖整个区间？
11. 年假/调休按哪个不可变账本快照时点出报表，跨任职余额归属哪个组织？

### P1：决定报表产品范围

12. 是否必须单独提供日报和周报？请给出字段、生成时点、补数截止和导出样式。
13. 部门/班组汇总按“发生时组织/组”还是“查询时当前组织/组”？员工月中调岗如何拆分？
14. 请假统计要展示单据明细、按人员/类型汇总，还是两者都要？跨月单据如何分摊天数/小时？
15. 是否需要独立早退、旷工、出差、外出、补签、调整来源、闭月差异报表，还是在明细/异常中筛选即可？
16. 正式页面是否必须具备组织树、员工、考勤组、服务端排序、条件标签、列设置和保存常用筛选？
17. 工作台恢复完整综合指标，还是只保留今日异常？正式大屏是否属于生产范围？
18. 导出只要 XLSX，还是还要 CSV/XLS、用户选列、矩阵样式、水印和固定留存期？
19. 九类报表最终列顺序、中文名、单位、小数位、空值及合计行分别是什么？
20. 小样本抑制阈值是多少，例如部门少于多少人不显示百分比？
21. 周六、周日、法定节假日各自的午餐/晚餐窗口、扣减分钟和触发门槛是什么？
22. 未结算、数据新鲜度和余额风险的红黄绿阈值是什么？

原始 PRD V1.0～V1.7 明确支持“排班内实出勤分钟 ÷ 有效应出勤分钟”，且有效应出勤扣除
已批准请假和按规则免打卡的外出；V1.8/V1.9 没有给出替代公式。仓库没有找到 V30 反向天数
公式的业务签字原文，因此 V30 只能按既有 checksum 作为历史迁移保留，不能作为公式已获认可的
证据。除此之外，人口/员工日分母、开放月截止、调岗人数去重、异常代码矩阵、全勤、周末餐扣、
签到排行、历史版本、舍入顺序和图表默认交互等新增问题，统一见下方确认单 R26～R43。

业务确认后，应形成一份版本化“报表公式与字段签字表”，同时更新迁移、Java 公式版本、自动化测试和客户验收样例，不能只改页面文字。

可直接填写的选项、建议默认值、影响说明和回复模板见
[`2026-08-06 报表业务口径确认单`](../contracts/2026-08-06-reporting-business-confirmation.md)。
