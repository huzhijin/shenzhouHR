━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

### 1. 登录与组织

- 登录方式是本系统独立账号密码登录，不依赖致远 OA SSO。
- 需要用户名/密码、显示/隐藏密码、忘记密码或联系管理员、首次改密、密码过期、失败锁定、会话过期和退出状态。
- 致远 OA 组织架构仅用于期初 Excel 导入。导入发布后，由本系统独立维护组织和人员。
- 本期不存在组织定时同步、手动持续同步、双向同步和 OA 组织变更同步页面。
- 取消组织同步不等于取消 OA 考勤业务单据接入。请假、加班、外出、出差、补卡等仍可以作为只读数据来源展示。
- 二次入职必须建立新的任职周期并保留历史。

### 2. 规则配置共同模型

所有相关规则采用通用 HR 软件式的类型化配置：

- 策略模板、版本号、草稿、已校验、已发布、已停用；
- 公司、地点、考勤组、政策组等作用范围；
- 生效日期、失效日期、优先级和覆盖关系；
- 冲突检测、影响人数、样例员工试算、发布确认；
- 变更原因、操作人、操作时间、审计和回滚；
- 已月结/冻结期间保护；新规则不能静默改写历史结果。

配置界面只能使用受控字段、枚举、数字、时段、开关、分段表格和规则组合，不设计允许管理员执行任意代码的脚本编辑器。

特殊城市、特殊员工或特殊作息通过加入有有效期的考勤组/政策组解决，不设计隐藏的个人硬编码例外。

### 3. 考勤组、班次和晚餐

- 夏令时、冬令时通过考勤组下的班次版本和生效日期管理。
- 支持不同地点和班组拥有不同作息，但需显示作用范围和生效期。
- 所有考勤组默认启用晚餐扣除。
- 晚餐扣除的启用、时间窗口、扣除时长、触发门槛，以及工作日、周末、法定节假日是否适用均可配置。
- 设计中必须显示默认值、继承来源、当前有效版本和下一版本。

### 4. 每月迟到宽限

- 每名员工每个自然月默认有 1 次迟到宽限机会。
- 默认仅命中迟到大于 0 且不超过 15 分钟的记录。
- 迟到超过 15 分钟不消耗该机会，按正常迟到规则处理。
- 默认员工在当月切换考勤组时不重置已使用次数。
- 次数、阈值、统计周期、作用范围、命中顺序均可配置。
- 日明细和月汇总中要能解释“本次使用宽限”“本月剩余 0 次”“未命中原因”。

### 5. 单边缺卡

- 单边缺卡指某个计划工作段只有上班卡或只有下班卡，而不是整天完全无卡。
- 默认补正期限为异常发生后 7 个自然日，期限可配置。
- 期限内状态为“待补正”，并展示截止时间和可接受的证据来源。
- 逾期且没有有效、符合时效的业务单据时，默认仅将缺卡对应工作段转为旷工，不默认整日旷工。
- 补正期限、期限口径、逾期结果、影响工作段/整日和管理员修正能力均可配置。
- 页面必须用易懂文案解释该概念，不只展示技术术语。

### 6. 假别与年假

- 所有假别均可配置计量单位、默认计算口径、最小申请单位、资格、证明材料、发放方式、有效期、结转、失效、销假、取消、冲突和余额规则。
- 默认按工作日计算。
- 年假资格与年假档位必须在 UI 中明确分开：
  - 资格门槛：最新任职周期在本公司连续任职满 1 年；可配置，默认启用、默认 12 个完整日历月。
  - 档位依据：累计工龄，不是只看本公司工龄。
- 累计工龄 = 最新任职周期本公司工龄 + HR 维护的入职前累计工龄。系统不设计公司外工龄证明审核流程，但维护和导入要留审计。
- 默认档位：
  - 满 1 年且不足 10 年：5 天 / 40 小时；
  - 满 10 年且不足 20 年：10 天 / 80 小时；
  - 满 20 年：15 天 / 120 小时。
- 默认在最新入职周年日发放，有效至下一周年日前一天。
- 二次入职从最新入职日重新计算资格和周年周期。
- 周期内累计工龄跨档时默认不立即补差，下一个周年周期使用新档位；该行为可配置。
- 年假规则预览必须同时展示资格结果、累计工龄、命中档位、发放日期、到期日期、天数和小时数。

### 7. 期初时间余额

- 支持员工期初工时、调休、年假等时间账户余额 Excel 导入。
- 需要模板下载、上传、字段映射、员工匹配、预校验、错误报告、差异预览、幂等、防重复发布、导入批次和审计。
- 余额详情必须展示来源批次、发生额、余额、单位、业务日期、有效期和冻结状态，不能只显示一个可直接覆盖的最终数字。

### 8. 离线/异构考勤机打卡 Excel 导入

- 用于无网络地点、无法连接 API、非得力或不同型号考勤机产生的原始打卡流水。
- 它与组织/员工期初导入、时间账户期初余额导入是三个独立入口和流程，不能混在一个“通用导入”页面。
- 导入的是原始设备打卡事实，不接受迟到、早退、缺卡、旷工、加班时长等结果，也不能代替补签申请。
- 必须提供真实、版本化的标准模板下载区，展示模板版本、更新时间、字段说明和合成示例。参考模板：`outputs/attendance-import-template-v1/神州HR_考勤打卡导入模板_V1.0.xlsx`。
- Open Design 只设计模板下载、版本和字段说明体验，不重新生成或修改 `.xlsx` 文件。
- 支持标准模板和其他厂商 `.xlsx`；其他厂商文件通过字段映射、设备人员/员工匹配及可保存的厂商/型号/地点映射方案归一化。
- 导入页面必须展示：总行数、有效、错误、完全重复、疑似重复、员工未匹配、设备未映射、冻结期间和可发布数量。
- 批次状态至少包含：草稿、校验中、待确认、校验失败、发布中、已发布、部分成功、失败、冻结期间阻断和已作废。
- Excel 与得力 API 必须跨来源去重；原始行和全部来源证据继续保留，并可从考勤明细跳转到导入批次及原始行。
- 涉及冻结/已月结期间时允许上传预检，但默认禁止发布或静默重算，页面应引导有权限用户按流程重开期间。
- 上传、预检、发布、作废/冲正、查看原始文件/原始行和下载错误报告是不同权限动作。

### 9. 薪资边界

- 薪资可以在后端预留，但当前前端完全隐藏。
- 不得在导航、路由、首页卡片、全局搜索、通知、报表、移动端或员工个人中心展示薪资、工资条或相关入口。
- 旧薪资页面统一标记为 `FUTURE_RESERVED`，当前不继续生成、不纳入路由。
- 不得用“功能未开放”占位页暴露薪资模块存在。

### 1. Excel 导入向导

组织/员工期初导入、时间账户期初余额和离线考勤打卡均复用统一向导骨架，但必须拥有各自的 route、模板、字段和发布规则，不能混成一张页面。

通用六步骨架：

`下载模板 → 上传文件 → 字段与员工匹配 → 预校验 → 差异确认 → 发布结果`

必须设计：成功、部分错误、文件级失败、重复批次、幂等命中、错误报告下载、离开草稿后恢复、发布确认和审计入口。预校验不直接改正式数据。

离线考勤专用流程进一步展开为：

`下载标准模板/选择映射方案 → 上传并选择地点、设备、时区 → 字段与设备人员/员工映射 → 预校验及 API/Excel 跨来源去重 → 错误和影响确认 → 发布到原始事实层`

离线考勤页面必须包含模板下载卡、字段映射、映射方案保存、预检统计卡、错误行表、重复/疑似重复对比、冻结期间提示、受影响员工/日期预览、发布确认、批次列表、批次详情、原始行和规范事件跳转。

### 2. 规则配置生命周期

统一任务流：

`选择模板 → 新建版本 → 配置参数 → 绑定范围 → 冲突检测 → 样例试算 → 影响预览 → 发布确认 → 生效/停用/回滚`

页面始终展示状态、版本、生效期、作用范围、继承来源、最后修改人和历史版本。已月结期间要显示保护说明，不能提供会静默改写历史的按钮。

### 3. 高风险操作

发布规则、批量导入、人工调整、重算、月结、反月结和导出均使用明确确认层，展示作用范围、人数/记录数、期间、影响、操作者和是否可逆。危险按钮不能与普通保存按钮颜色和位置混淆。

### 4. 解释性体验

考勤结果、迟到宽限、单边缺卡、年假资格和年假档位都要提供“为什么”入口，展示输入事实、命中规则版本、计算过程、结果和可操作下一步；不要只给红色标签。
