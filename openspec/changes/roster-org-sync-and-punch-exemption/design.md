## Decisions

### 1. 组织原地发版本，保留 `organization_id`

现网已经是父子树，只是名字脏。按路径把致远节点映射到花名册短名：去掉 `服务中心-`、`工程一部-`、`上海` 等前缀后，与花名册路径对齐则**同一 `organization_id` 插入 `effective_from=2026-01-01` 的新 `organization_version`**（新 name / 必要时新 parent），关掉当前版本。

只在花名册有、现网没有的路径上新建身份（如昇州维修部、仓储原物料仓/成品备品仓）。花名册没有且无人挂靠的节点（晟州「审批」空壳、无人的「总经理」等）从 `2026-01-01` 停用，不删除身份。

备选：整棵新树新 ID。否决：任职、数据范围、历史报表事实都挂着现网 `organization_id`；换 ID 会让在用管理员的授权和已出快照对不上，员工侧也会感觉「人还在、部门变成另一个对象」。

映射规则（神州）：

```
现网 code/path                         花名册短名链
…/服务中心                             服务中心
…/服务中心-工程一部                    服务中心 / 工程一部
…/工程一部-MATCH组                     服务中心 / 工程一部 / MATCH组
…/工程一部-MATCH组-MATCH1组            服务中心 / 工程一部 / MATCH组 / MATCH1组
董事长室                               董事长
```

晟州：`上海总经办`→`总经办`，`上海RD1`→`RD1`，`上海销售部`→`销售部`，审批空壳停用。

### 2. 人只改当前员工与任职，不改打卡行

- 部门只是改名、仍挂原叶子：不插新 `employment_assignment`。
- 人换了叶子（马雨从晟州销售部到神州新品部、叶剑从昇州总经办到神州总经办等）：关旧任职 `effective_to=2026-01-01`，开新任职。`employee_id` 不变。
- 打卡、得力绑定、OA 仍挂原 `employee_id`。
- 9 名花名册没有的人：任职结束，**不删员工、不停用账号、不改密码**。
- 新员工（赵子奇等）：只建员工+任职，不调用开通账号接口。
