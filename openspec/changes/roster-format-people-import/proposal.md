## Why

现场人事无法新增人员、无法新增部门，现有「组织与员工期初导入」又吃不了花名册：四套编码模板、组织和人必须分三次导。9 月神州、聚能已有新人要进系统，本地 `神州花名册.xlsx` 已过期。现在要让手工新增能用，并用一份花名册格式的表把部门和人一起导进去。

## What Changes

- 员工「新建」必须能选任职部门（及入职日期）；不能再建成没有任职的空壳。
- 部门「新建」按名称和上级挂树；组织编码由系统生成或选填，不再把编码当人事必填项。公司和上级部门必须属于同一家公司，失败要给出可读原因，不能再表现为无响应或权限拒绝。
- 菜单隐藏现有六步「组织与员工期初导入」。旧编码导入接口可留在后端，前台不再入口。
- 新导入入口仍在组织与人员下。下载模板必须是花名册表头（一份 xlsx，不是四套）：序号、公司名称、工号、姓名、一级部门、二级部门、三级部门、组别、职位、入职日期。空层级用 `/`。
- 同一文件可含多家公司；部门和人员一次预检、一次确认后写入。冲突（工号姓名不一致、部门路径歧义、跨公司重名等）必须先提示，确认前不写正式主数据。
- 用新导入（或等价发布）写入：神州截图 `SZST0731`–`SZST0747`（张立强 `SZST0743` 挂技术支持中心 / 现场服务部 / 武汉产品服务组，职位空）；聚能 `SZJN0042`–`SZJN0046`。`聚能-` 前缀去掉。`研发一部` 对齐现有 `RD1`；`硬件组` 在其下新建。

## Capabilities

### New Capabilities

- `people-local-create`: 本地新建员工必须带任职部门；本地新建部门以名称和上级为准，编码不再阻断操作。
- `roster-people-import`: 花名册格式模板下载、上传、预检冲突、确认后同时写入部门与人员；前台隐藏期初导入。

### Modified Capabilities

无。主库 `openspec/specs/` 目前没有可改的人员/导入需求规格。

## Impact

- 前端：`EmployeesPage` 新建表单、`OrganizationPage` 新建表单、`/people/import` 从六步向导换成花名册导入；菜单不再展示期初导入文案。
- 后端：员工创建 API 增加任职；组织创建放宽编码；新增花名册解析/预检/发布（可复用现有 import batch 骨架，不复用四套编码模板字段）。
- 数据：神州 9 月新人 `SZST0731`–`SZST0747`、聚能 `SZJN0042`–`SZJN0046`；不改打卡、OA、密码、已发布报表投影。
- 不改芯越组织、不改账号批量开通、不把「副岗」列入模板（截图有、旧 Excel 无）。
