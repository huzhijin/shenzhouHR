## Why

现场仍有大量纸质加班申请单进不了系统，人事只能对着照片手抄；OA 与得力仍按 0 点/12 点对时，白天单据和班次卡进报表要等半天才重算整月。报表中心只能选整月，加班页按人汇总，看不到一单一行，也无法只重算近几天。

## What Changes

- OA 考勤单据定时同步改为**每小时一次**，得力打卡改为 **8 / 12 / 18 / 0 点**各一次；两侧都继续走现有水位线**增量**，不改成全量重拉。
- 每次定时增量成功后，自动重算改为默认**近 3 天**（相对今天、上海日历），不再等「同一 12 小时槽里 OA 和得力都成功」才整月重跑。关账/已确认月份跳过。
- 新增人事用的**纸质加班单**录入：主表挂附件并识别，明细带出一单一行。可手填，也可上传 PDF/照片（可多张、可同时识别）。同一张单可挂多个文件只服务这一行的识别，不拆成多笔加班。
- OCR 用 Paddle/百度云（先可用庆峰已有凭证试跑，生产走环境变量；密钥不进仓库）。勾选加班类型（加班费 / 调休 / 义务加班）；认不清则类型留空。
- 人名+部门模糊匹配：重名列出候选（工号、标准部门、在职状态），人事确认或换人后部门跟花名册。不隔离、不自动拍板。
- 保存门槛：类型空、人未确认、必填日期/起止缺失、**同一人重叠自然日**（含过夜单占到的每一天，含已有 OA/纸质单）一律报错，**不能强制保存**。
- 仅 `HR_ADMIN`（人事）可编辑纸质单；加班统计查询与报表加班页按**单据明细**展示（一人多日多行），含纸质来源，不按人汇总。
- 考勤报表中心增加起止日期筛选（不要只能选整月）。展示合计按所选日期窗口内的日事实相加。
- 「重新计算」拆成三个按钮：**近 3 天 / 近一周 / 本月**。窗口相对今天；跨月时未关闭的上月可以写入；只重算窗口内日事实，窗口外日事实不动，月合计用旧日+新日重加。

## Capabilities

### New Capabilities

- `scheduled-incremental-sync-windows`: OA 每小时、得力 8/12/18/0 增量同步；成功后默认近 3 天自动重算。
- `paper-overtime-ocr-entry`: 纸质加班主表附件识别、明细带出、手填、模糊匹配、保存门槛、人事可写。
- `overtime-document-detail-display`: 加班统计与报表加班页按单据行展示（含纸质），不按人/部门汇总块。
- `report-date-range-and-partial-recalc`: 报表中心起止筛选；近 3 天/近一周/本月局部重算与日事实合并加总。

### Modified Capabilities

- `sync-auto-recalculate`: 12 小时双源门 + 整月自动重算改为按次增量成功后的窗口重算。
- `overtime-hours-from-snapped-oa-form`: 纸质加班小时与 OA 加班同一套取整区间减餐扣。
- `report-query-pages`: 加班查询列出纸质单；单据明细一行一张单。

## Impact

- 同步：`OaAutoSyncJob` / `DeliAutoSyncJob` 默认 cron、`application.yml` 与钉死 cron 的测试、部署 env 示例。
- 自动重算：`AttendanceReportAutoRecalcService` 槽位与触发条件；核算引擎支持日期窗口并合并已发布日事实。
- 纸质加班：新表/证据链（或独立来源写入 `oa_attendance_document` 同类加班证据）、OCR 适配器、匹配服务、REST、能力码、HR_ADMIN 授权。
- 前端：纸质加班录入页（主表附件+识别，明细行）；报表中心起止日期与三个重算按钮；加班表改为单据明细。
- 查询/工时：纸质单进入加班明细与日事实；月度工时仍用日事实加总（工时公式不变）。
- 密钥：`PADDLE`/`BAIDU` OCR 仅环境变量；庆峰本地 key 只用于试跑，不提交。
- 不改 OA 插件填单、得力身份绑定、关账月强制重开、工资引擎。
