## Context

查询报表已有「忘打卡」（缺卡事件清单）、「年休假 / 调休额度」（账户余额）。人事还要三张**统计表**：忘打卡按考勤明细的上午/下午格子看漏刷和补签；年假、调休按自然年看额度与分月已休，并在详情改额度、留流水。

现网年假/调休期初是 **2026-07-31 账、作为 8 月期初**（导入生效日 2026-08-01）。1–7 月没有本系统流水。出勤率统计表本轮不做。旧查询页全部不改。

约束：查询列表只读已钉住核算；改额度走员工假期活账户（已有 `ANNUAL_LEAVE:ADJUST` 与 `/annual-leave/adjust`、`/time-off/adjust`）。列表与详情数字可能短暂不一致。

## Goals / Non-Goals

**Goals:**

- 三个新菜单、新路由、新查询 API；旧忘打卡 / 年休假 / 调休额度 / 考勤明细 / 请假汇总不动。
- 忘打卡统计表：人×日、一格两段；正常无底色；漏刷段着色并写「漏刷」；补签红字。
- 年假统计表、调休统计表：按人一年一行；点进详情可调额度并写流水。
- 分月已休 1–12 列都在；账期前（1–7 月）显示 `/`，账期起未休显示 `0`。
- 新员工折算列无值显示 `0`。
- 查询 GET 不核算；按人分页。

**Non-Goals:**

- 做出勤率统计表。
- 改现有任何查询页或考勤明细格子合同。
- 在忘打卡统计表里改打卡（人事改卡仍走明细/改打卡）。
- 为 1–7 月补历史已休。
- 拆新的改额度能力（继续 `ANNUAL_LEAVE:ADJUST`）。
- 改额度后立刻重算并刷新 pin。

## Decisions

### 1. 三个独立 sheet / 路由，挂在旧页下面

| 菜单 | 路径 | sheet |
|------|------|--------|
| 忘打卡统计表 | `/attendance/queries/missed-punch-stat` | `missed-punch-stat` |
| 年假统计表 | `/attendance/queries/annual-leave-stat` | `annual-leave-stat` |
| 调休统计表 | `/attendance/queries/time-off-stat` | `time-off-stat` |

菜单键紧挨旧项。可见性仍是 `ATTENDANCE_REPORT_QUERY:READ` 整组开放，不另拆菜单能力。

备选：旧页加 Tab。否决，明确要求新菜单且旧页不动。

### 2. 忘打卡统计表复用明细日格合同，只画漏刷/补签/时间

读与考勤明细相同的上午/下午段（`morning` / `afternoon` 的 `text`、`tone`、`punchAt`）：

| 段状态 | 文案 | 底色 |
|--------|------|------|
| 有打卡、非漏刷非补签 | `HH:mm` | 无 |
| 漏刷 | `漏刷` | 漏刷色 `#be6cbb`，只涂该段 |
| 补签 | 红字 `补签HH:mm` 或 `补签` | 无底色 |
| 休息日/请假覆盖该段 | 空或时间，**不算漏刷** | 本表不铺假别色 |

假/出差/外出覆盖的段不得标漏刷（与明细优先级一致）。默认只返回本月至少有一段漏刷或补签的人。筛选：漏刷 / 已补签 / 上班漏 / 下班漏。按人分页，禁止一次拉全月全员格子。

点姓名打开月历详情，同一套段规则。

备选：`0 / 0.5 / 1`。否决，已改为对齐考勤明细。

### 3. 年假与调休列不同；分月 1–12 都在，账期前用 `/`

账期截止：`openingInclusiveFrom = 2026-08-01`（7 月 31 日期初的 8 月账）。某月 `< 2026-08` → 单元格 **`/`**；某月 `>= 2026-08` 且无已休 → **`0`**；有已休 → 天数或小时（与列单位一致）。

**年假统计表列：** 序号、一级部门、二级部门、姓名、入职日期、公司工龄、公司外已证明工龄、累计工龄（年）、按累计工龄当年应休天数、新员工计算年休假日历天数（空则 **0**）、可休天数、可休小时数、1–12 月已休。

**调休统计表列：** 序号、一级部门、二级部门、姓名、期初小时、加班转入小时、可休天数、可休小时数、1–12 月已休。不套工龄档、应休、新员工折算。

页头可保留「今日」与「年休假计算日」（当年 12/31）。查询选**自然年**。

`/` 比 `0` 直观：账期前不是「已休 0 天」，是「本账没有这段流水」。Excel 导出同样写 `/`。

### 4. 详情改额度：活账户 + 现有调整 API + 流水

抽屉读 `GET .../employees/{id}/annual-leave?year=` 或 `.../time-off`。调整走已有 POST `.../adjust`（`adjustmentHours`、`year`、`reason` 必填、幂等键）。流水用账户 `entries`。

无 `ANNUAL_LEAVE:ADJUST` 只读。列表仍读 pin/年报快照，抽屉展示活余额，文案说明「可休以详情为准，列表随下次核算更新」。

备选：查询页自己写一套调整接口。否决，会双写口径。

### 5. 查询仍只读 pin；按人分页

忘打卡统计走日格/日事实，按员工 `LIMIT`。年假/调休走时间账户事实 + 工龄/任职（年假）+ 按月已休聚合。无 pin 时与其它查询页一样提示核算未完成，不在 GET 里跑引擎。

## Risks / Trade-offs

- [Risk] 列表可休与详情活账户不一致 → 抽屉标明活数据，不在保存后同步重算整月。
- [Risk] 忘打卡统计若按人返回 31 天两段，560 人会慢 → 默认只出有漏刷/补签的人，页大小与明细相当。
- [Risk] `/` 被当成缺数错误 → 表头/图例写清「8 月账期前无流水」。
- [Risk] 调休套用年假工龄列会误导 → 调休表独立列集。

## Migration Plan

- 纯增量：新路由、新 sheet、新 GET。无库结构变更（用现有 pin 与假期账户）。
- 回滚：下线三个菜单即可，旧页不受影响。

## Open Questions

- 无。1–7 月展示 `/`、新员工折算空为 0、不出勤率统计表、改额度复用现接口均已确认。
