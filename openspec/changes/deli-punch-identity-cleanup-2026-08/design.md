## Context

线上江苏神州 2026-08 月报已经按两份得力 Excel 互补对过：对得上花名册的人里，Excel 有卡的人天约 92.7% 首末一致。剩下「表有卡、格子全空」主要不是公式，而是认人。

已经对上的事实：

- 彭伟 `SZST0335`：8/1–8/13 本人格子空；早退时刻与赵艺娴 `SZST0289` 相同（设备打出别人的工号）。8/14 起本人卡对得上。
- 陆玉蕾 `SZST0284`、李扬 `SZST0291`、王善源 `SZST0694`：同一刀切（约 8/12 前空，8/14 后对）。陆玉蕾历史上挂过汪立青 `SZST0285`。
- 代码已写「确认绑定优先于 empno」，但 **8/1–8/12 的 raw 已经按错误 empno 落库或隔离，水位走过，日常 00:00/12:00 增量不会回头**。
- 短 CHECKIN `user_id` 387 不能当目录 id（彭伟 vs 周步新）。七月冲突工号补录用的是得力雪花账号 id，不是短号。
- 黄凯是 Excel 工号写成 663；花名册 667 已对，不需要清系统卡。
- 于跃 Excel `SZST0664`、花名册 `SZST0671`（0664 是周易钊）：对账按姓名，回放按花名册。

约束：得力 cron 保持 00:00 / 12:00；不改花名册工号；不伪造打卡。

## Goals / Non-Goals

**Goals:**

- 新卡：雪花人员绑定唯一时，打卡进绑定员工，即使条上 empno 是别人的。
- 旧卡：2026-08-01 起至绑定生效日的得力 raw，按当前绑定回放，错挂挪走、隔离转有效，同一 `source_record_id` 仍只有一条有效事件。
- 回放后重算 2026-08，月报首末与互补 Excel（按花名册认人）一致。
- 验收清单至少含：彭伟、陆玉蕾、李扬、王善源、居军、张晨阳。

**Non-Goals:**

- 改得力设备工号或 Excel 文件。
- 聚能月报矩阵 500（另案）。
- 工作台午前日切。
- 外出抵旷工、加班小时 0（计算口径，认人修完后再对）。

## Decisions

### 1. 认人顺序：确认雪花绑定 → 唯一 empno → 隔离

与现有 `EvidenceResolutionPolicy` 一致，补齐的是 **绑定数据** 和 **回放**，不是再发明第三条匹配键。

目录雪花（长度 ≥ 16 的数字 id）可以写入 `employee_binding.deli_user_id` / `deli_ext_id`。短 user_id 不写入、不覆盖 empno。

备选：只用 empno——已证明彭伟/陆玉蕾会进错人。  
备选：用短 user_id 当目录 id——387 会把周步新的卡给彭伟。

### 2. 先种绑定，再回放 raw，再重算

顺序不能反：

1. 从七月冲突工号映射 + 得力人员目录，为错挂人员写入 **confirmed** 绑定。
2. 扫描该 source、时间窗内全部 raw（含 QUARANTINED 和已 MATCHED）。
3. 按当前策略重算 match；若员工变了，关掉旧 effective、写新 effective；若从隔离变为匹配，补 effective。
4. `POST /api/v1/attendance-reports/recalculate` 江苏神州 2026-08（回放碰到的其他公司一并重算）。

只重算 = 继续漏刷。只重拉增量 = 水位跳过旧 id。

### 3. 回放按 `source_record_id` 幂等，不按「天」搬末卡

彭伟和赵艺娴同一天可能各有卡；不能把赵艺娴当天末卡整段切给彭伟。只能按得力原始记录的人员雪花重挂。

实现落点：独立应用服务（例如 `DeliPunchReplayApplicationService`），走与 ingest 相同的 `EvidenceResolutionPolicy`，写 match_decision 新版本，effective 事件以 source raw id 为幂等键。

### 4. 回放窗口默认 2026-08-01 00:00+08 ～ 绑定生效日（含 8/13）

8/14 起新卡已经能对上，仍应允许窗口延伸到「今天」以便隔离积压一并消化。不得早于 `kq-ingest-not-before`（2026-08-01）。

### 5. 验收对账按花名册，不按 Excel 工号

互补合并：月报有时刻用月报，空/漏刷时用汇总表时刻。  
姓名覆盖：黄凯→667，张晨阳→663，于跃→0671。  
失败条：Excel 有 `HH:mm`、矩阵首末都空。

### 6. 错挂目标员工的卡要留下属于他们自己的记录

挪走彭伟那条 source_record 后，赵艺娴若还有自己的 raw，应保留。回放不得按姓名删除整天。

## Risks / Trade-offs

- [绑定种子用错雪花] → 只用七月已核过的 source_account_id 和目录 employee_num 双对上的行；对不上的列入人工确认表，不自动绑。
- [赵艺娴少一张其实是她的卡] → 只挪 source_record 级；验收时抽赵艺娴 8/1–8/13 是否还剩自己的上班卡。
- [回放漏隔离原因] → 回放后仍 QUARANTINED 的列出 reason + empno + 雪花 id，不得静默丢。
- [大窗回放锁表] → 按日或按 source_record_id 分页；不改日常 cron。
- [067x–070x 整月空白可能不是错 empno] → 回放后仍 DELI_ONLY 的单独列出（可能无 raw、实习号、或不在绑定表），不假装已清。

## Migration Plan

1. 部署认人/回放代码（功能默认关，不自动扫全库）。
2. 在目标库写入 confirmed 绑定（可重复执行）。
3. 跑 2026-08-01..2026-08-13（或至今天）回放。
4. 重算 2026-08。
5. 用两份 Excel 互补脚本验收；失败人天必须为 0（对得上花名册且 Excel 有时刻的）。
6. 回滚：绑定可标停用；effective 事件有 raw id，可再按旧 match 回放。不回滚得力原始 raw。
